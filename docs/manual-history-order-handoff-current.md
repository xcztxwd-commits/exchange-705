## 2. 不可改变的业务合同

- 后台订单管理新建**已平仓模拟合约单**，直接保存 `CLOSED`、`MANUAL_TEST`，不走真实开仓/平仓，不冻结资金、不释放从未冻结的保证金。
- 用户支持 ID、邮箱搜索并同时显示；品种来自实际配置，不自动把用户举例的符号改成另一个品种。
- 输入包括时区、开平仓分钟、方向、杠杆、手数、仓位百分比、目标净收益。开平仓均取对应分钟 K 线的 `open` 起点参考价，不是精确成交承诺。价格缺失时明确失败，不能用当前价、邻近价或零替代。
- 时区只解释输入和显示；存储及公共权益分桶维持 UTC。处理跨日、夏令时重复或不存在时刻，不能静默挪时间。
- 手数、比例、净收益联动，允许超过 100% 仓位、超过可用资金的手数、突破普通杠杆上限；仍检查正值、步长、精度、溢出和无解。可用资金不大于零时比例不可计算，但不禁止手数/收益驱动。
- 钱包固定 `CONTRACT`。输入收益、钱包变更、历史调整全部使用扣一次手续费后的净收益；订单毛盈亏与手续费分别保存，避免重复扣费。
- 两个开关每次打开新建表单均默认关闭。合法组合只有：都关、只开钱包、钱包和历史都开。历史开时必须钱包开，前后端都约束；后端不能擅自替非法请求开启钱包。
- 钱包开时只增加净收益一次，可得负余额；`frozen` 不变。钱包关时订单仍进入用户历史仓位。
- 历史开关名称和含义为“添加到历史权益观察值”，不是所有收益统计是否计入的总开关。仅主动调整 `asset_history_1m/1h/4h/1d`。
- 平仓所属分钟及之后、入账前已存在的有效历史观察值各加一次净收益，不是只改一个点，不是把后续全设置成同一个数。将来正常采样直接读取已入账的钱包，不再额外加一遍。
- 平仓分钟无有效权益时，从该分钟向前找最近非空权益，最多 24 小时，包含恰好 24 小时前。零和负值有效；没有则基础为零。只补该目标分钟，不补满整个缺失区间；不借用其他用户或目标分钟之后的数据。此兜底仅适用于权益，不适用于行情。
- 受影响的已结束、满足归集条件的小时/4 小时/日周期必须正确修复 OHLC、极值时间和计数。边界桶按修正后的下级数据重算，不能简单给四个值全加收益。保持封闭周期归集、正常延迟和公共游标，不生成未来数据或回退全站水位。
- 数据库与实际使用的 PC/移动端用户历史仓位标记“手动订单”。后台保留创建入口及明确结果；不扩展资金明细、代理业绩、交易额、分享等标记链，不擅改现有统计口径。
- 负余额正常保存和显示，普通订单资金限制不变，真实强平及强平清零规则不变。手动创建本身不得清零；如果扣款使原有真实持仓随后满足强平条件，继续按原强平规则执行。

## 3. 最小实现与数据安全

复用现有预览/创建接口、组件、计算及归集器。控制器保持薄，纯计算独立可测，应用服务编排事务，历史适配集中处理四表；不要增加单实现接口、工厂、通用账本、永久虚拟权益层、异步平台或新 UI 框架。

预览展示实际净收益、目标差额、资金与历史影响。创建由服务端校验参数、权限、报价和账户版本，不能相信前端计算金额。滑块变化不应每次重复请求外部行情。网络报价不得占用资金事务和全局历史锁。

订单、钱包、历史和必要审计必须同一真实数据库事务。核对 JPA/JDBC 是否共享连接，不能只看 `@Transactional`。协调采集/归集锁、账户锁及版本，保证提交/回滚后释放。幂等键持久化：同键同内容返回原结果，同键不同内容拒绝，并发重试不重复入账。

服务端内测总开关默认关闭，专用后台权限校验，普通用户/代理不能绕过。仅隐藏按钮不算安全控制。

数据库先确认实例、库名、版本与迁移状态；必要变更采用增量脚本。已应用迁移不改写、不重复修改金额；MySQL DDL 不当作可随订单事务回滚的 DML。只备份受影响的代码、结构和数据，不复制整个磁盘或依赖目录。
