# 控盘 V3：固定随机幅度区间、均衡轨迹与精确终点

日期：2026-09-28。状态：V3 核心路径已实现并在隔离环境执行测试；实测结果和未覆盖项见第 13 节。本文件前 12 节保留原设计与验收标准，不能将其中的计划表述视为已通过的证据。

## 1. 需求与范围

### 1.1 已确认的语义

- “波动率”在本功能中是波动强度档位，不是金融统计意义上的收益率标准差。
- 强度决定每秒绝对涨跌额的随机下限和上限，而不是整段价格的最低价和最高价。
- 同一任务的区间启动后固定，不随进度、剩余秒数、当前价格或目标距离变化。
- 允许小幅调整方向选择倾向；不能通过后段放大幅度、收缩幅度或末秒补差完成目标。
- 允许连续上涨或下跌。不要求每秒独立，不承诺精确终点条件下仍保持无条件均匀抽样。
- 用明确的窗口指标检验“均衡”；不承诺随机样本在视觉上绝对均匀。

### 1.2 V3 保证的阶段

本方案用于起点、终点均已确定的 TARGET 阶段。STOP、手动偏移、目标完成后的 HOLDING、真实行情恢复属于独立阶段，不能把目标阶段的保证扩展到未知的未来行情。

自动恢复和旧恢复逻辑保持原行为、单独标识。不允许把“原始实时价格 + 有界偏移”宣传成全价受 V3 限幅。若未来要求恢复也限幅，需要允许延期对齐真实行情，另立变更。

### 1.3 明确不采用

- 进度包络 `4p(1-p)`、末尾衰减包络。
- `max(目标价差/时长, 起点价格比例)` 自动扩大随机幅度。
- 最后一秒补齐总差额。
- 碰到非法价格后直接截断为最小价格。
- 成功率不足时悄悄退回 V2、扩大区间或放松均衡条件。

## 3. 参数与整数价格刻度

### 3.1 定义

```text
S：起点价格刻度
T：目标价格刻度
N：执行秒数，即涨跌步数；价格点共 N+1 个
Δ = T-S
q = 10^(-pricePrecision)：一个价格刻度对应的金额
I：强度，1～10
a、b：每秒绝对涨跌额的最小/最大刻度，1 <= a <= b
m = (a+b)/2：区间中心，可保留为有理数
seed：启动前独立生成并保存，不依赖实际启动毫秒
```

价格、增量、累计总和使用 `BigInteger` 刻度或等价精确运算，不使用 double。当前请求允许较大的价格和八位小数，不能默认乘以 10^8 后仍能装进 long。随机概率可用 double，但不能参与金额守恒与最终验收。

目标超过币种精度直接拒绝。起点取统一展示/执行口径的可表示价格；若源价含更多小数，必须与报价层统一归一化并展示归一化起点，不能在启动瞬间悄悄改变已承诺的执行价。

### 3.2 强度映射（建议首版默认值，需按币种验证）

```text
基础典型金额 = 启动时价格 × r
典型金额(I) = 基础典型金额 × I
未量化下限 = 典型金额(I) × 0.9
未量化上限 = 典型金额(I) × 1.1
a = ceil(未量化下限/q)
b = floor(未量化上限/q)
```

`r` 建议初值 0.00001，可使用已存在的币种配置能力保存覆盖值；不要为本需求搭建新配置平台。r 是拟议调参起点，不是已验证适用于所有品种的常数。

以起点 100000、两位小数为例：强度 1 对应 0.90～1.10；强度 5 对应 4.50～5.50；强度 10 对应 9.00～11.00。幅度计算不使用目标价差或执行时长。

- `a>b` 或 `b<1`：`AMPLITUDE_PRECISION_UNREPRESENTABLE`，不能偷偷提高到一刻度。
- `a=b>=1`：只能随机方向，金额退化为单一刻度。预览明确标识“当前精度不支持金额随机”；不得宣称金额有连续随机变化。
- 档位量化后可出现相同区间，要求区间随强度非递减，不承诺每个币种十档都严格不同。
- 正下限代表每秒不能原地不动。若未来需要静止秒，必须显式修改语义；首版不暗中引入零步。

## 4. 可行性：先判定，再生成

### 4.1 方向数量的必要且对无路径约束的金额总和充分条件

设上涨步数 U，下跌步数 D=N-U：

```text
U*a-D*b <= Δ <= U*b-D*a
```

等价得到 U 的整数候选范围：

```text
ceil((Δ+N*a)/(a+b)) <= U <= floor((Δ+N*b)/(a+b))
```

注意负数除法应实现数学上的 ceil/floor，而非 Java 向零截断。

“均衡随机”首版要求 U>=1 且 D>=1。因此 N=1 或只能单向到达的任务应返回明确提示，不能包装成有双向随机性的任务。旧版本一秒任务仍按旧语义运行。

### 4.2 同时约束整段典型幅度

只满足总和可能使所有幅度挤到区间边缘。增加总绝对变化量 V：

```text
V = 所有上涨金额之和 + 所有下跌金额绝对值之和
上涨总量 G+ = (V+Δ)/2
下跌总量 G- = (V-Δ)/2
```

对每个候选 U，检查是否存在整数 V 满足：

```text
max(2*U*a-Δ, 2*D*a+Δ, ceil(0.97*N*m)) <= V
V <= min(2*U*b-Δ, 2*D*b+Δ, floor(1.03*N*m))
V 与 Δ 同奇偶
```

优先选接近 `N/2+Δ/(2*m)` 的可行 U；V 优先靠近 N*m。不要仅选一个 U 失败就宣布全部不可行。可扫描最多 N+1 个整数，避免笛卡尔积搜索。

如果没有 U/V，返回 `TARGET_AMPLITUDE_INFEASIBLE`：参数在金额/典型幅度约束下不可行。建议调整目标、时长或强度；不得保证“延长一秒一定解决”，正下限和离散性可能形成可达空隙。

价格正值、窗口均衡、可选价格边界的可行性还需要路径生成验证；上述检查并非完整路径存在性证明。

## 5. 整段轨迹生成

### 5.1 生成守恒的涨跌幅度池

分别生成：

- U 个区间 [a,b] 内的上涨金额，总和精确为 G+。
- D 个区间 [a,b] 内的下跌绝对金额，总和精确为 G-。

实现建议：先用固定 seed 生成区间内整数候选，再在所有未触边元素间分配总差额，按剩余可调整量批量分配；末余数以随机排列的元素顺序分散。禁止一刻度一刻度循环处理巨大差额，禁止固定把余数分给列表尾部。

因为目标组总量在 `[数量*a, 数量*b]` 内，整数修正可精确完成。修正后再次断言范围与组总和。金额随机性会受总和条件约束，不承诺各金额均匀或独立分布。

### 5.2 动态概率用于生成时的排序，而非运行时重新抽样

当前已选 t 步，价格 P，剩余 R=N-t 步，其中 Urem 个上涨步：

```text
B = S + Δ*t/N                 // 仅用作方向反馈参考
e = P-B
pBase = Urem/R
correction = 0.05 * clamp(e/(10*m), -1, 1)
pUp = clamp(pBase-correction, 0, 1)
```

- 高于参考线，额外减少最多 5 个百分点的上涨选择倾向；低于参考线相反。
- 5 个百分点为拟议初始反馈强度，不是最终条件概率相对初始值的全程上限。库存比例本身会变化。
- 若某方向无剩余步骤或无法满足当前硬约束，只能选合法方向；最后一步可能被条件完全决定。这是固定终点的必然约束，不能宣传“每秒始终保留相同方向概率”。
- 剩余上涨/下跌金额池整体总和守恒，因此任意使用完全部元素的排列仍准确到达终点。
- 使用 swap-remove 从池中取元素；采用有界随机候选选择，不引入每秒排序或全池扫描的 O(N²) 常规路径。

### 5.3 选择候选时的硬过滤

1. 增量绝对值仍在 [a,b]。
2. 下一价格不低于一个价格刻度；如有明确价格边界，同时满足边界。
3. 本步完成的 10 秒、30 秒窗口通过第 6 节指标。

遇到死路：撤销当前候选或重新排列；仍失败则重新生成幅度池。不得截断价格、裁剪末步、扩大边界。

建议首版最大尝试 32 轮，并设单调时钟计算预算（暂定 5 秒，实测调整），两者任一到限即终止。每轮和每步候选次数也必须有界。失败返回 `PLAN_SEARCH_EXHAUSTED`，仅表示预算内没有找到方案，不表示数学无解。

实现中保存算法、映射与验收参数版本；成功计划的持久化内容是运行与重启的权威数据。不能在重启后因机器速度不同而重新搜索另一条路径。

### 5.4 精简伪代码

```text
snapshot = resolveAndValidateStartBasis()
parameters = quantizeAndFreeze(snapshot, target, duration, intensity)
(U, D, V) = findFeasibleCountsAndVariation(parameters)

within bounded attempts and compute budget:
    up = boundedRandomIntegers(U, a, b, sum=(V+Δ)/2)
    down = boundedRandomIntegers(D, a, b, sum=(V-Δ)/2)
    steps = feedbackOrderWithWindowChecks(up, down)
    if independentValidate(steps, parameters):
        plan = immutablePricesAndSummary(steps)
        revalidateSnapshotAndCommit(plan)
        return success

return structuredFailureWithoutStartingTask()
```

生成与验收必须分开实现；验收器不应复用生成器的“是否合格”布尔标记来证明正确。

## 6. “均衡”的可执行验收标准

记 d[t]=P[t]-P[t-1]、v[t]=abs(d[t])、μ=V/N。均衡针对 v，不针对带方向的净涨跌。

### 6.1 每条成功轨迹必须全部满足

1. 点数 N+1；P[0]=S；P[N]=T。
2. 每步 `a<=v[t]<=b`，包括第一步和最后一步。
3. 所有价格可按币种精度精确表示且为正。
4. 总绝对变化均值 μ 在区间中心 m 的 ±3% 内。
5. 对所有完整滚动窗口 W∈{10,30}：窗口 v 的均值位于 μ 的 ±3% 内。
6. N>=3 时，前、中、后三段按索引尽量等分，各段 v 均值均位于 μ 的 ±3% 内。
7. 有上涨也有下跌；不会要求每个窗口都同时涨跌，除非后续另加明确业务限制。

以上 3% 是拟议首版“均衡容差”，不是用户已经指定的数值。所有百分比用整数交叉相乘检查，例如 W 窗口总量 X：`97*W*V <= 100*N*X <= 103*W*V`，避免浮点比较和隐藏容差。

不足 10/30 秒的窗口不伪造数据。N=2 仍检查每步、整体和双向要求；N>=3 检查三段。小样本/粗精度可能导致严格均衡不可行，按错误分类处理，不悄悄添加 q 的容差。

若所有窗口和三段均值都在 μ±3% 内，任意两段的均值差最多为 6%μ。不能把此标准说成“幅度绝对相同”。

### 6.2 统计观察项，不作未经校准的硬承诺

- 前中后三段 RMS 幅度、幅度分位数和幅度随时间的回归斜率。
- 正负各自幅度分布、最长连续方向次数、价格偏离参考线的最大值。
- 首步/末步处于 a 或 b 的频率，检查是否有隐含端点特殊处理。
- 多 seed 条件下的早/中/晚幅度分布偏差。

约束条件会改变随机分布，不能将样本与独立均匀分布直接比较并据此判错。仅观察均值也不能证明整个概率分布完全一致。

### 6.3 K 线口径

“每秒幅度”是相邻逻辑秒价格差，而不是未收盘分钟 K 线的 high-low。分钟高低差会累积，同样的单秒幅度在持续同向时也可能形成较大的分钟振幅。方案不承诺每分钟高低差相同。

## 7. 时间、持久化、读取与一致性

### 7.1 时间定义

```text
P[0] 生效：startedAt
P[k] 生效：startedAt + 1000*k
plannedEnd = startedAt + 1000*N
index = clamp(floor((now-startedAt)/1000), 0, N)
```

目标“按时”指逻辑行情时间和任务采样时间，不是承诺网络、调度器和页面在该毫秒绝无延迟。另测端到端发布延迟。

生成完成后再确定 startedAt，不把生成耗时算进任务时长。虚拟分支不能先取整 now 再误删首步；允许复用持久计划的毫秒锚点，所有调用统一索引计算。

### 7.2 启动事务

1. 短读取获取起点、币种精度、当前任务版本/状态、映射配置快照。
2. 在全局锁和数据库长事务之外生成轨迹。
3. 按币种锁短事务重查任务状态、幂等键及起点。
4. 起点/配置/任务已变化则返回 `START_BASIS_CHANGED` 或有界重试，不平移旧计划、不变更目标。
5. 原子保存计划、V3 任务及起点样本；失败全部回滚。
6. 完成提交后才允许对外执行新计划。

预览与启动之间也必须重验起点。若展示的是未锁定种子的候选路径，应标注“预览”，不能保证正式轨迹相同；固定区间与可行性摘要可明确展示，正式结果以提交后的摘要为准。

同一 requestKey 的重试返回原计划，不能生成新路径。同一幂等键不同参数拒绝。新配置只影响新任务。

### 7.3 计划保存

拟新增 `market_control_plan`，以 task_id 为主键，保存：

```text
algorithm_version / schema_version
seed
parameters_json：起点、终点、精度、N、I、a/b、r、容差、反馈系数、映射版本
prices_json：N+1 个整数刻度字符串
summary_json：最高最低、最大单秒涨跌、实际上下行次数、窗口指标
checksum：规范化参数与价格序列的 SHA-256
```

建议价格序列用 MEDIUMTEXT，不用 TEXT 承载最长 86400 秒计划。BigInteger 以字符串编码，避免 JavaScript 大整数精度损失。测量实际 payload 和内存后再决定是否需要压缩，不先加压缩依赖。

运行时按计划加载一次、数组索引取价。缓存按内存预算限制，不能按每秒构建完整 BigInteger 数组；缓存丢失读取持久计划。缺失或校验失败时停止执行并报警，绝不重新随机生成替代计划。

当前项目由 `ControlHistoryStore.migrate()` 执行 `create_control_history.sql`；不是已确认存在 Flyway 自动版本迁移。应按现有机制追加幂等建表，并验证 H2/MySQL。虚拟历史事件引用同一 planId，不复制 86401 点到每个事件的 JSON 中。

### 7.4 计划与历史隔离

计划中未来价格仅供管理员预览。`market_control_sample`、行情接口、K 线、订单执行只读取已经生效且按现有事务语义提交的点，不提前写入/发布未来数据。

目标截止后的 HOLDING/恢复继续按阶段规则，不应被 `index=N` 永久冻结。采样调度漏过几秒时补齐逻辑历史点；用户观察到的跨秒跳变可能大于单秒 b，必须展示/检查时间间隔，不能把网络延迟误判成逐秒算法越界。

- 可行性及错误分类，建议调整项。
- 选定档位候选计划的点数、起终点、最大涨跌、最高最低、前中后三段均值、滚动窗口范围。

先用公式评估十档，再只为选定档位生成完整候选，避免每次表单变化构建十条全天路径。预览做防抖和请求序号控制，陈旧响应不能覆盖新参数。

界面保留“波动强度 1～10”，增加说明：“决定每秒绝对涨跌额的随机范围，整个任务不变”。显示“均衡随机 V3”和真实区间，不能只显示档位。

随机开启时新任务使用独立 seed；关闭时使用规范化参数导出的固定 seed，得到确定性均衡排列，不使用任务时间改变路径。界面明确“关闭后为固定可复现排列，不是直线”；V1/V2 既有任务语义不变。

未来路径预览仅允许有控盘权限的管理员访问；普通行情、历史和任务状态接口不泄露尚未发生的计划价格。

## 9. 失败分类

| 错误 | 含义 | 行为 |
|---|---|---|
| INVALID_PARAMETERS | 非法时长、强度、价格、精度 | 拒绝，不生成 |
| AMPLITUDE_PRECISION_UNREPRESENTABLE | 档位区间没有可表示的正刻度 | 显示实际精度，拒绝自动放大 |
| TARGET_AMPLITUDE_INFEASIBLE | 无 U/V 满足金额及全局幅度约束，或无法双向随机 | 显示目标/时长/强度冲突 |
| PLAN_SEARCH_EXHAUSTED | 有限搜索未找到满足窗口/正价等全部条件的路径 | 不启动，不声称已证明无解 |
| START_BASIS_CHANGED | 预计算后起点或任务状态发生变化 | 刷新或有界重试 |
| PLAN_CORRUPTED | 持久计划缺失/校验失败 | 禁止发布伪造替代价格，报警 |

所有失败均不影响已有任务，不写成功历史，不消费成功幂等结果。

### 10.2 样例基准

在精度 2、S=100000、T=100060、N=60、强度 10、r=0.00001 下：

```text
a=900 刻度（9.00）
b=1100 刻度（11.00）
典型幅度=1000 刻度（10.00）
可选 U=33、D=27、V=60000 刻度
G+=33000、G-=27000
```

先用 33 个 +1000 和 27 个 -1000 构建守恒/均衡的确定性夹具；再测组内金额随机变化的生成器。该夹具仅证明有可行路径，不证明随机生成器已实现或通过。

反例：N=3、a=b=1、Δ=0，虽然 |Δ|<=N*b，但不存在三步 ±1 和为零；必须拒绝，避免只用距离上界作可行性判断。
