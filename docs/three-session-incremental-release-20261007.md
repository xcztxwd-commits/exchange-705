## 2. 两库分别补充一个字段

使用本次专项字段补丁 `V2026100703__withdraw_wallet.sql`。执行前确认列不存在；如果已存在，检查类型、长度、空值约束和默认值完全一致后跳过，禁止重复盲跑。

字段定义：

```sql
ALTER TABLE withdraw_record
    ADD COLUMN account_type VARCHAR(20) NOT NULL DEFAULT 'FUND';
```

历史提现默认属于 `FUND`。无需修改已有余额，也不需要单独执行历史数据 UPDATE。实施时优先限定 `ALGORITHM=INPLACE, LOCK=NONE`，不支持时停止评估，不自动退回 COPY；设置较短的元数据锁等待超时。MySQL 5.7 添加普通列支持这一方式，但仍会重建该表，并可能等待元数据锁，不能承诺零锁定。[MySQL 5.7 官方说明](https://docs.oracle.com/cd/E17952_01/mysql-5.7-en/innodb-online-ddl-operations.html)

短暂暂停新增提现和提现审核，等待相关请求结束，再对这张表做备份、DDL 和校验。校验原有列逐行值与备份一致、新列均为 `FUND`，索引、外键、触发器保持原定义；恢复请求前确认新后端健康。DDL 在 MySQL 5.7 中不能依赖普通事务 ROLLBACK 撤销。

本次专项补丁独立记录数据库目标、SQL SHA、实施时间及前后字段核查，不修改 `tenant_schema_version`、最低应用 epoch 或业务激活状态。现有公开结构快照仍是 0702 基线，不把其校验通过描述为包含 0703 字段的完整结构验收。
