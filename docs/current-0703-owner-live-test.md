# 既有 0703 的当前测试环境验证

适用目标仅为主库 `1090`：真实 MySQL 5.7、已存在且完全符合发布 SQL 的 `0703/0703_1`、所有旧版本就绪、最新版本未就绪。仅用于用户明确确认无真实用户、授权上线且保护历史的环境。Java 8 / Boot 2.7.18 和正式发布门禁保持原规则。

`current_scope_audit.py` 对当前带租户列的 schema 检查 manifest 所有私有所有者、关系及实际外键；关系依据各自 NULL 语义去重。缺列、跨库外键、非零计数、缺失/重复输出或传输失败均拒绝，保留原 SQL 与逐查询结果。不能用旧迁移前的 legacy 扫描替代当前审计。

`current_0703_activation.py` 提供三个顺序操作：

1. `observe`：要求实际 MySQL `read_only=1` 且所有其他会话排空。核对停写现场库存、目标容器/UUID/数据挂载、当前源码/既有迁移哈希和用户原指令；创建独占全库备份，恢复至新建且物理独立的 MySQL 5.7，再比较所有表、字段、NULL、十进制原精度、token、版本、期限、触发器及存储对象。观察收据不声称过去迁移已完成。
2. `record-startup`：同一主库只读状态下实际启动已测试的完整 JAR，核对健康、容器/镜像/JAR SHA、真实目标连接和非 SUPER 账户、限定启动时间内的实际日志。验证容器须显式配置静态 IPv4；收据同时保存启动时真实地址和网络 ID。Docker 停机后清空运行地址，`activate` 核对同容器保留的静态配置与原网络 ID，网络集合、网络 ID、静态配置改变或动态地址均拒绝。源码或备份改变即拒绝；此操作不证明交易资金或前端绘制验收。
3. `activate`：先停止上述同一只读应用、排空连接；再次核验全库/独立恢复/原件/启动事实，先持久记录固定身份的 intent，再对既有最新 `0703` 就绪位执行一次 CAS。核对只影响一行，其他历史字段与全部定义完全一致。失败/不确定 intent 均禁止自动重试；输出和侧文件只使用同一 canonical 路径，并拒绝文件 symlink。

参数和约束以 `--help` 和源文件为准。授权文件包含用户原指令、24 小时内有效期、真实停止的写者库存/恢复负责人、固定观察与激活路径、`c.target` 生成的两端物理身份、当前源码/迁移 SHA 和已测构建收据 SHA。授权材料不能从示例复制成自称已经停写的证据；先保存实际 Docker 状态、MySQL 会话和维护只读结果。

构建收据要求 `TESTED_CURRENT_FULL_JAR_BINDING`，包含后端源码 SHA、整 JAR SHA、封存源清单、制品清单，以及 `backend_build/related_backend/physical_mysql/orm11` 四类原件引用。每个原件都必须列入路径/SHA 清单：校验实际命令退出码、Maven package 原日志、选定后端全部 JUnit、三组必需物理 MySQL 用例各自实际执行，以及原 ORM 11 组/Java8命令/输出 SHA。仅填 `PASS` 或零错误数字不能通过。H2、全 skipped、缺失原件或失败原件不能证明物理 MySQL 验证。

月线删除使用已有 `monthly_retirement.py` 独立预览/停写/备份/精确清理流程。未经可靠识别的记录保持原值。该激活工具不删除月线、恢复历史、启动写者或打开正式生产发布许可。上线后仍需 PC/移动端各五分钟只读实测，报价配对到实际绘制严格 P95<3000ms；未绘制版本单列。Demo 缺列/历史未就绪状态及缺少认证夹具的场景不能被本主库收据覆盖。
