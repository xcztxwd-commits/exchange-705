# 后台菜单与按钮权限

## 已实现

- 基础后台按 7 个一级目录、24 个二级页面组织：运营总览、客户与代理、交易与行情、资金管理、信贷管理、理财管理、系统与权限。
- 同目录中的客服功能通过独立目录注册器扩展“客服与消息”，不覆盖其并行开发内容。
- 基础权限目录包含 107 个操作能力。新增、编辑、删除、审核、导出、资金修改、银行卡和地址操作分别授权。
- 查询、筛选和刷新沿用所在菜单的查看权限；取消、关闭和个人会话操作不要求业务写权限。
- 前端隐藏无权按钮并拦截点击；后端独立验证，不能通过显示隐藏按钮、伪造本地管理员标记或直接请求接口绕过。
- 后端按请求读取授权，撤销下次请求生效；前端导航重新校验，打开页面每 30 秒刷新权限。权限加载失败时关闭访问。
- 保留代理数据归属检查和超级管理员专属操作；委派管理员不能授予自己不具备的权限，也不能提升为超级管理员。

## 使用

1. 用超级管理员进入“系统与权限 / 角色与权限”。
2. 新增或编辑角色，打开“分配权限”。菜单只授予查看，按钮必须逐项勾选；勾选一个按钮不会自动授予同级其他按钮。
3. 在“管理员账号”选择该角色。代理账号继续在“客户与代理”的权限设置中分配菜单和操作。
4. 原有菜单授权保留；没有自动为旧角色开放新写权限。升级后应显式补齐业务所需按钮。

## 启动与数据库

`AdminPermissionCatalog` 启动时幂等同步目录、页面和操作定义，并保留旧菜单 ID、既有授权和停用状态。`admin_menu.menu_code` 映射已扩至 150 字符。现有环境启用了 Hibernate `ddl-auto=update`；若目标环境禁用自动 DDL，应先将该列扩至 `VARCHAR(150)`。

本次未替换正在运行的 Docker 服务，也未对业务数据库实施迁移。当前目录存在其他功能的并行修改，避免将其未完成版本一并部署。代码统一构建并重启后，目录同步才作用于运行环境。
