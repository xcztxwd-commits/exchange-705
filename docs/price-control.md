# 定时控盘与恢复行情

后台「AI 控盘」支持目标价格、渐进恢复和原有的手动偏移。执行时长为 1–86400 秒，波动强度为 1–10 的整数等级，不是点数或百分比。

- 目标价格：从启动时的有效控盘价出发，每秒更新。关闭随机震荡时匀速变化，不受波动强度影响；例如 90 到 100、10 秒，每秒增加 1。到期达到目标，保留完成时的最终偏移，之后随原始行情涨跌。
- 开启随机震荡：默认关闭，开启后中途可随机涨跌，也可越过目标。强度 1 也有轻微扰动，等级越高偏离匀速路径越大；起点和终点不变。随机路径由启动时间、品种和秒序号确定，同一任务的多个读者及重启后得到相同路径，价格按品种精度处理并保持正数。时长过短（例如 1 秒）或价格精度较低时，可能观察不到中途涨跌。
- 渐进恢复：以当前控盘价与当前原始行情的差值作为起始偏移，按指定时长将偏移收敛到 0，也支持独立设置随机震荡和波动强度。关闭震荡时偏移匀速归零；原始行情在此期间继续变化，恢复的终点是届时的原始价格。完成后关闭控盘；可以接替运行中的目标任务。
- 停止任务：保留停止时的偏移，继续跟随原始行情。一键恢复原始行情：立即终止任务、关闭控盘并清零偏移；行情不可用时也可执行。

报价、成交价和实时推送共用服务端计算；WebSocket 每秒推送，不增加上游行情请求频率。控制不会使过期或不可用的源报价重新成为有效成交价；行情故障时拒绝开始任务、停止并保留偏移和交易，已到期任务等待有效行情完成。

任务参数（含随机震荡开关）保存在数据库，刷新页面不会中断，并会回填当前任务的时长、强度和开关。服务端重启按原始开始时间继续，停机期间到期的任务在源行情恢复后完成。数据库只在启动、停止、恢复和完成时更新，不逐秒写入。币种编辑不会覆盖控盘设置；数据库版本字段防止并发配置修改互相覆盖。控盘接口受 `ai_control` 菜单权限保护；未来目标和任务参数不会出现在公共币种接口中。

历史 K 线继续沿用已有行为：当前窗口按当前偏移整体平移，更早历史接口返回源行情；不记录逐秒控盘走势，刷新图表不会保留这些走势。本次未新增历史行情账本。

强度算法：仅在开启随机震荡时，匀速价格加上零均值随机扰动；幅度为平均每秒价差（最小为起终点较低价的 0.01%）乘以 `2 × 强度`，再乘以 `4 × 进度 × (1 - 进度)`，确保两端扰动归零。恢复任务对偏移使用相同规则。开关未传入时默认关闭；旧记录字段为空也视为关闭。

## 发布与验证

同步发布后端与管理端。数据库关闭自动建表时，执行 `exchange-backend/src/main/resources/db/manual/705-price-control.sql` 中缺失的列；现有 `ddl-auto=update` 也会新增它们。原有偏移配置不重置，历史订单不重算。此实现沿用单后端的行情缓存；部署多个副本前需要增加配置同步。

后端针对性测试：`mvn -Dtest=PriceControlTest,ExecutionQuoteTest,QuoteStateTest,ShareHistoryTest test`（Java 8）。管理端：`npm run build`。

浏览器检查脚本为 `exchange-admin/tests/aiControl.browser.cjs`，使用 5191 端口的管理端开发服务并拦截全部 API 请求，覆盖震荡开关、强度、启动、刷新回填、停止、恢复、故障期间立即恢复及手动偏移。页面截图位于本地 `reports/price-control/admin-restore.png`。数据库与接口回归使用隔离的 MySQL 5.7，运行 `MinimalFixRegressionTest#timedControl*`。

2026-09-20 完整复测通过：16 项行情与路径测试（含真实计时器自动完成）、37 项隔离 MySQL 回归，共 53 项，无失败或跳过；管理端 TypeScript/生产构建和浏览器操作检查通过。修复了清空波动强度后关闭随机震荡仍被强度校验阻止提交的问题。浏览器接口使用模拟响应，后端使用隔离数据库和模拟行情源，不代表现有运行服务已完成端到端验收。检查现有运行后端包，尚不包含新控盘控制器及路径计算类，新功能尚未部署。
