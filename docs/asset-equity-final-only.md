# 历史权益：分钟收尾快照与仅封闭归集

本说明覆盖旧设计中的每分钟第 5 秒采集和当前桶草稿规则。

## 采集

每分钟 UTC 第 0 秒触发。例如 10:02:00 的任务将快照归入 bucket_start=10:01:00；observed_at 保留实际读取时刻，不回拨成 10:01。这是业务归属约定，不表示数据实际在 10:01 观察到。

调度和批量读取存在耗时：同一任务允许在 10:02 这一采集分钟内完成，真实延迟体现在 observed_at；排队、行情准备或读取跨到 10:03 的批次丢弃，不再补写 10:01。10:03 的新任务仅采集归属 10:02 的快照。漏采保留缺失，不能事后用当前余额重建过去。唯一键仍保留首条记录，不覆盖旧分钟。

## 归集

- 小时：整点后 1 分 20 秒归集已结束小时。
- 四小时：UTC 00/04/08/12/16/20 点后 2 分 20 秒归集。
- 日：UTC 00:03:20（北京时间/新加坡时间 08:03:20）归集前一 UTC 自然日 [00:00, 次日 00:00)。
- 每五分钟恢复任务仅处理已经到期的封闭区间，不写当前草稿。
- 上级使用下级已完成水位及 finalized=1 记录；持久化桶/用户游标保留失败续跑和幂等性。
- 采集锁仍占用时归集暂缓，防止未提交的分钟记录被漏封闭。

每分钟采集不再触发其他表归集。OHLC 算法与 UTC 周期边界不变。

## 查询与切换

小时、四小时、日查询仅返回已经结束且 finalized=1 的区间。窗口边界修正仅针对已存在的正式父区间，不能从分钟数据合成当前草稿。独立 live 点保留。

旧分钟记录、已封闭记录不改写；旧草稿不删除，但查询忽略。旧草稿到期后由原有水位归集覆盖成正式记录。首个切换分钟若已有旧观察点，唯一键保留该点。
