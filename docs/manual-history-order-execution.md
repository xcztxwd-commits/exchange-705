## 2. 固定业务合同

以下规则不能被“优化”成另一种功能。字段/类名可依项目规范调整，业务含义不得改变。

### R01. 直接创建已平仓合约单

后台订单管理的合约区域新增“新建已平仓模拟合约单”。选用户时支持 ID/邮箱搜索，并显示 `ID · 邮箱`；选择实际配置的品种，不硬编码 `BTH`，不假定每手等于一个币。

服务端创建 `contract_order`，状态固定 `CLOSED`，来源固定 `MANUAL_TEST`，保存方向、开平仓价格/时间、手数、杠杆、每手数量、保证金、手续费、换算率和盈亏快照，关闭限价匹配。不经过普通开仓/平仓、撮合或资金冻结；不能返还从未扣过的保证金。

### R02. 历史取价和时区

开平仓都按所选分钟 K 线的 `open` 取起点参考价，不是精确第 0 毫秒成交价。报价只读，使用现有历史行情链路及其合并规则；无该分钟数据时明确不可创建或等待，不用当前价、任意邻近价、0 或随机值替代。

输入精确到分钟，开仓不晚于平仓，不能使用未来时刻。API 非分钟精度输入不能静默改时间后下单；返回明确校验错误。允许同一分钟开平仓按相同价格计算，手续费仍正常计入。非固定兑换品种必须使用对应历史换算率；不可用时明确报错。

IANA 时区下拉参与服务端解析，默认系统配置时区而非管理员电脑的隐含时区；保存绝对 UTC 时刻和输入时区。DST 不存在时间拒绝，重复时间要求选择明确偏移。切换显示时区保留绝对时刻。公共权益桶仍按 UTC 划分，`created_at` 仍为实际创建时间。

每手数量及手续费使用本次创建所采用的有效配置并存快照；本版不引入历史交易规则版本服务。不能默默假装还原了历史手续费配置。

### R03. 手数、仓位和净收益联动

提供手数、仓位百分比、目标净收益三种明确输入驱动方式，修改主输入后计算其他项，避免三个 watcher 循环互相覆盖。滑块支持超过 100%，初始 0–200% 只是显示范围，数字框更大输入可扩展范围。普通交易的上限不改。

允许超余额手数和突破普通上限的正杠杆；仍校验有限数、正手数、精度、步长及数据库溢出。手数步长沿用现有规则，当前为 0.01。目标收益无正手数解或无唯一可反算解时明确报错，不能改方向/价格凑数。步长取整后展示实际收益及差额。

V3 第 3.2 节公式为准：
- 仓位资金为保证金加一次手续费，分母是当前 `CONTRACT.available`，不是总资产或历史余额。
- 固定手数时，杠杆影响保证金，不再额外乘到毛盈亏上。
- 可用余额小于等于 0 时比例不可计算，禁用比例驱动，但按手数或净收益仍可创建。
- 最终计算使用后端 `BigDecimal`；前端结果仅为交互预览。不能信任客户端直接指定最终价格、利润、来源或状态。

### R04. 净收益与钱包

钱包固定 `CONTRACT`。订单 `profit` 保留现有毛盈亏语义，`fee` 单独保存；`N = profit - fee` 为净收益。输入目标、钱包变化及历史变化均使用同一 `N`。

钱包开启时仅执行 `available += N` 一次，`frozen` 不变。亏损允许余额变负，不重复扣手续费。每手数量快照不得为 NULL 后误入旧订单公式。

### R05. 开关联动

每次打开新建表单，钱包和历史开关默认均关闭：
- 都关：仅新增历史订单，不改钱包、不回填四表。
- 只开钱包：当前合约钱包入账，不回填过去；以后的真实采样自然反映余额变化。
- 两者都开：当前钱包入账，并按下文回填历史。
- 历史开、钱包关：非法。前端开启历史自动开启钱包并明确提示；历史开启时不能关闭钱包。后端直接拒绝非法组合，不偷偷开启入账。
- 关闭历史不自动关闭钱包，提交摘要清楚列出最终选择。

### R06. 历史调整的范围与交接

仅改目标用户、`net_equity_v1` 口径的 `asset_history_1m`、`asset_history_1h`、`asset_history_4h`、`asset_history_1d`。

设 UTC 平仓分钟为 T0。入账前已经存在的非空分钟权益，凡 `bucket_start >= T0`，各自增加一次 N；之前分钟不变。不是把后续值设为同一个金额，也不是每过一分钟再增加 N。

未来正常采样读取实际钱包，不挂永久加成、不再额外加 N。后来真实转账、亏损、强平照常影响权益。实时曲线点继续使用原有真实估值，不新增另一套实时总资产。

### R07. 目标分钟缺值

在本单 N 生效前读取基础：
1. 目标分钟非空，使用其现值。
2. 目标缺失或 NULL，从同用户、同口径的 `[T0-24小时,T0)` 查最近非空分钟。按 UTC 实际 24 小时，不逐分钟查 1440 次。
3. 没有则基础为 0；0 和负值均有效，不得只找正数，不读未来或其他用户的数据。

先对原本存在的非空范围执行加 N，再对原本缺失/NULL 的目标分钟写入“基础值＋N”，防止新补行被加两次。只补目标分钟，其他缺失/NULL 分钟保留。之前手动单的影响如果已经包含在基数中，不再重复汇总旧利润。

零基础/沿用基础是模拟估计，保存回溯源、基础值和创建证据，不声称恢复了未采集的真实历史；后来倒序补单按增量修改现有记录，不建立历史全量重演引擎。本规则绝不能用于行情缺值。

### R08. OHLC、收尾采集与补点来源

按所属周期是否结束判断，不按平仓后过了多久判断。UTC 11:20 属于 11:00–12:00 小时、08:00–12:00 四小时。显式修复旧已完成汇总；普通游标不会自动回头重算。必要时为新增旧分钟生成到期父记录，不回退全站水位、不填满空白日历。

保留当前仅封闭周期归集及正常延迟：小时 1 分 20 秒、4 小时 2 分 20 秒、日 UTC 00:03:20，下级未完成还要等。不能恢复旧草稿。完整覆盖且来源点不变的周期可整体平移；边界、补点和 NULL 修复周期须重算 OHLC、极值时间及样本计数。

当前收尾任务在下一分钟采集上一分钟，T0 对应 `bucket_start`，不是 `observed_at` 的分钟。按 V3 的最小方案，历史开启时只接受已经结束的平仓分钟；当前未结束分钟提示等待，不新增延迟订单任务。

人工补点保存逻辑生效时间及估算来源，真实观察时间和创建时间不能伪造。采用 V3 的 `effective_at`、必要的可空观察/批次字段或等价最小实现；所有分钟读取、归集、裁剪、期初和 `carryIn` 必须一致兼容。不能因 NULL 时间把补点过滤掉或映射成 1970 年。原始分项/失败证据保留，必要修正额独立记录。

正常采集如遇已补人工行，唯一键保留该行，不能覆盖或双加，不能把它误登记成第一条真实正权益基线。不能把可计算的估算点说成真实采样。

原图表 `carryIn` 是不限时长的展示沿用，不落库、不参加 OHLC；保持不变，不改为本业务的 24 小时规则。

### R09. 标记与不做的范围

数据库来源以及实际使用的 PC/移动端用户历史仓位显示“手动订单”。后台提供创建入口与提交结果，不另外扩展所有列表、资金明细、分享海报、代理业绩和交易金额的标记链。

不改现有已实现收益、代理或交易统计 SQL。手动 CLOSED 单可能按现有查询规则计入这些统计，这不是历史开关失效。历史开关只决定四表回填，不是所有收益统计的排除开关。新订单仍需被现有历史查询/排序正确返回。

### R10. 负余额、权限、原子性

负余额是真实合法余额，不截成 0、不当作快照读取失败。普通开仓仍限制资金充足，真实强平及强平后清零不变；手动创建自身不执行清零。不要求用户无持仓；如果扣款导致真实持仓满足强平条件，原规则仍会运行。

后台内测总开关默认关闭；按现有角色体系仅授权超级管理员或等价专用后台权限，不能落入允许 AGENT 的通用规则。普通接口不能伪造手动来源或调用该能力。

一次提交的订单、钱包、四表和必要审计同一事务。唯一幂等键加请求摘要：同键同内容重试返回原结果，同键不同内容拒绝，并发同键也仅生效一次。锁忙/超时要明确可重试，不能返回伪成功。

- `GET /api/admin/orders/contract/manual/context?userId=...`

服务端预览绑定操作者、用户、参数/报价版本和有效期，明确返回钱包及历史影响；客户端不能伪造预览后篡改金额。创建时校验账户版本、重新计算；发生影响结果的变化则要求重新预览，不偷偷改手数或利润。重复提交成功结果优先幂等返回，不能因钱包版本已变化再次扣款。

### 4.3 事务连接与历史修复

现有 `AssetEquityStore.locked()` 自己取得物理连接、提交事务，且获取锁失败直接返回。不能套一层 `@Transactional` 就当它与订单 JPA 原子；须明确共享真实事务连接、锁的所有者与生命周期，commit/rollback 后释放命名锁，异常路径也测试。不能复用会在中途多次 commit 的正常定时任务作为创建事务。

在该事务中读取基础、保存订单、钱包变更、调整范围及补点、修复到期父桶、保存审计。采用 V3 防双加顺序。正常 `saveBucket()` 的 finalized 保护保留，定点修复使用符合成熟条件的正式结果，不用草稿强写旧父桶。

范围按实际用户数据枚举，不因两个点相隔一年就补出一年空桶。预览显示条数；同步事务设置经过验证的处理上限和锁等待上限，超限明确拒绝，不静默截断或返回“已成功、后台再说”。本版不提前建设异步回填平台。

### 5.1 确定性算例

### 5.2 数据库/API 必测

1. 三种合法开关组合，非法组合由服务端拒绝；都关仍创建 CLOSED 手动单。
2. 钱包 50 加净亏损 -100 得到 -50，frozen 不变；不存在第二次手续费或保证金返还。
3. 已有 11:19=1000、11:20=1000、11:59=1050，N=100：分别成为 1000、1100、1150。
4. 11:20 缺失、11:19=NULL、11:18=800：补点 900；其他 NULL/缺失分钟不被补满。
5. 找不到基础时盈利 100 得到 100，亏损 -100 得到 -100。恰好 24 小时、超出 24 小时、0、负数、其他用户、不同 basis 和未来点分别断言。
6. 目标已有有效值与 NULL 修复两条路径；补点不能被范围 UPDATE 再加一次。
7. 同键连续/并发重试、同键不同请求、不同订单同一分钟、多笔倒序补单；订单行、审计行及钱包/历史增量均正确。
8. 故障注入于订单后、钱包后、分钟后、父桶处理中；每处失败全部回滚，幂等记录不残留假成功，锁释放后可重试。
9. 真实采集与创建、归集与创建、普通钱包操作与创建并发：不丢更新、不读半成品、不死锁；事务结束的下一次实际采样不再加一遍 N。
10. 小时/4 小时/日边界、跨日、正负 N、边界桶 OHLC、极值时间及计数、窗口裁剪一致性；11:00–11:19=1000、11:20–11:59=1100 的小时结果必须 O=1000/H=1100/L=1000/C=1100。
11. 旧 finalized 父桶实际得到修复，未结束/未满足延迟或下级水位的桶不提前生成；正常任务不会覆盖错误或回退游标。
12. 人工有效时间、真实 observed_at、created_at 分离；读取不丢 NULL 观察时间的补点，旧/新序列不倒序，估算来源可追溯。
13. 正常采集重复碰到人工分钟不覆盖/双加、不污染真实基线；现有图表不限时长 carryIn 不变。
14. 普通资金不足下单仍拒绝；有真实持仓的用户允许手动创建，后续真实强平与清零结果不变，不残留虚拟加成。
