# 独立全功能模拟账户：设计与实现

## 1. 需求结论
不是给真实账户加一个余额开关，也不是单独做简化版现货页。一个登录身份，对应两个隔离的业务账户环境：REAL 与 DEMO。模拟环境复用现有全部账户业务引擎、页面与校验；只替换资金来源、实名准入和真实世界出入金动作。

- 登录后可以进入模拟环境；不要求实名，也不把用户伪装成“实名通过”。
- 真实账户的登录会话、封禁、令牌失效规则仍是身份来源。
- 真实业务继续执行原来的实名规则；模拟豁免只能由服务端进程配置启用。
- 账户选择按用户、浏览器标签页保存。切换不转移余额、持仓、订单或待提交表单。
- 不是无痕零延迟切换：为彻底清除旧请求、Pinia 状态和行情订阅，采用整页重载；不等待已有交易请求结束。

## 2. 功能覆盖与行为

| 功能 | 模拟账户实现 |
|---|---|
| 账户资产 | 独立 FUND、CONTRACT、OPTION 子账户；首次各发放 100,000 虚拟 USD 记账单位，仅一次 |
| 品种 | 同步真实业务公开品种定义，覆盖 Crypto、Metal、US、Forex、CFD、Oil，以及后台新增分类 |
| 合约 | 共用 ContractOrderService；买卖、市价/限价、杠杆、改单、撤单、止盈止损、强平和历史 |
| 期权/秒合约 | 共用 OptionOrderService；上涨/下跌、期限、冻结、到期结算和历史 |
| 定价和费用 | 共用数量精度、最小数量、规格版本、保证金、换汇、佣金和报价新鲜度规则；行情不可用时拒绝成交 |
| 账户划转 | 仅在模拟环境三个子钱包之间划转；沿用锁、幂等键和记录，不允许 REAL/DEMO 互转 |
| 充值 | 同一充值订单与入账凭据流程，自动确认虚拟入账；无需付款截图；返回的收款地址为不可用的 SIMULATION 标记 |
| 提现 | 同一余额、费用、绑定归属校验；虚拟扣账后直接 COMPLETED，不执行任何真实银行或链上出款 |
| 理财 | 同一申购、冻结、计息任务、赎回、违约费用及历史 |
| 贷款 | 模拟身份豁免，申请、签约后自动虚拟放款；沿用利息、还款及历史逻辑；不是实际授信或贷款合同 |
| 钱包和账户资料 | 模拟数据库中的独立记录，不复制真实银行卡、地址、证件、历史交易 |
| 订单分享 | 使用同一分享模板，额外强制绘制 SIMULATION · VIRTUAL FUNDS ONLY 图片水印 |
| 登录/改密码 | 共用真实身份系统，不建立可独立登录的模拟身份密码 |
| 历史 | 切换和重新登录不重置；采用已有分页、软删除、归属校验。补充模拟资金通过虚拟充值完成 |

“所有实际账户功能”指账户业务操作与计算规则复用，不代表真的汇款、提现、授信或制造实名记录。管理员操作、真实身份验证和外部机构实际执行不模拟成真实成功。

旧简化 `/demo` 页面已退出入口并重定向主页面；原有 legacy demo 后端与历史数据保留，不做破坏性迁移，也不把旧现货记录伪造成新合约持仓。

## 3. 架构

```text
同一客户端、同一登录身份
  REAL 请求 /api      -> backend      -> 实盘 MySQL / Redis / uploads
  DEMO 请求 /demo-api  -> demo-backend -> 独立 MySQL / Redis / uploads
                          |
                          +-- GET 实盘 /api/simulation/session：验证当前会话
                          +-- GET 实盘 /api/simulation/catalog：公开业务规格
```

同一份 Spring Boot 应用部署两次，不复制交易实现，不引入动态切库 ThreadLocal。定时任务、线程池、异步结算天然使用所在进程的数据库，避免跨线程丢失账户模式后写入实盘。

### 部署级隔离
- 模拟 MySQL 独立容器、库名 exchange_demo、独立账号和密码；该账号只授予模拟库权限。
- 模拟 Redis、上传卷独立，不使用实盘 Redis key 前缀凑隔离。
- demo-data 内部网络只连接模拟存储；demo-identity 连接身份服务；demo-web 连接客户端网关。
- 模拟进程不加入实盘默认数据网络，也不持有实盘 MySQL 凭据。
- 开启 simulation.enabled 时启动检查数据库名必须以 `_demo` 结尾；配置错实盘库直接拒绝启动。命名检查不能替代上述账号权限与网络隔离。
- `/demo-api` 上游缺失或故障返回错误，绝不回退 `/api`。
- 模拟本地注册、登录、后台管理、改密码在最早的过滤器被拒绝；不存在通过模拟令牌进入实盘的授权路径。

### 身份、实名和请求边界
- 前端 DEMO 标记不授予权限；后端验证真实登录会话，再在模拟库按同一 UID 幂等建立独立记录。
- 模拟身份用 `demo-UID@example.invalid` 和不可登录的密码占位，KYC 仍为 NOT_VERIFIED。
- 豁免返回 `simulationExempt=true` / `SIMULATION_EXEMPT`，从不保存 APPROVED 实名记录。
- 业务 API 校验 X-Account-Mode；真实服务拒绝 DEMO 业务请求，模拟服务拒绝 REAL 或缺失模式的业务请求。
- 公共行情读接口、行情 WebSocket、只读批量行情和健康检查为明确例外。
- 每次模拟认证依赖真实会话校验；会话服务不可用则拒绝新的业务请求，不降级为未验证身份。已存在的模拟结算任务仍独立运行。

## 4. 数据与一致性

### 独立实体
复用现有 user_account、asset_account、contract_order、option_order、transfer_record、deposit_record、deposit_credit_record、withdraw_record、financial_order、loan_record 等完整 schema，但全部存在于模拟库。跨环境同 UID 的记录不代表共享资金账户。

新增 simulation_seed：user_id 主键、amount_per_wallet DECIMAL(32,16)、created_at。开户、三个钱包和 seed 标记在同一事务中完成；用户行锁和唯一键保证并发首次进入只发一次初始资金。任何失败全部回滚。

### 配置同步
首次进入同步、之后请求触发的最多每 60 秒一次同步。允许表仅为 trading_symbol、option_duration、loan_setting、financial_product，以及三个公开 system_config 键。保留产品 ID，更新规格，不删除订单。源已下架/删除的定义在模拟端停用。

不复制用户、证件、银行卡、API 密钥、支付收款目的地、管理员、活动预算。控盘和随机行情控制字段清空/关闭，模拟环境使用自己的行情链路；不能将模拟结果描述为实盘必然成交结果。已有订单的结算快照仍由原引擎保存。

### 缓存与请求
- Axios、批量报价、直接行情 fetch、WebSocket 使用同一账户 API 基址。
- 划转重试键包含环境与 UID；切换后不会重放到另一个环境。
- 选择账户后整页重载，取消旧页面响应消费，销毁旧订阅和缓存。
- 其他标签页登录身份变化触发当前页重载；不同标签页账户模式可独立。
- 已提交请求即使客户端退出，其后端事务仍可能完成；切换提示明确说明“在原账户执行”，不可凭断网断言失败。
- 上传文件返回 `/demo-uploads`，始终指向模拟上传卷；不会拿模拟文件 ID 查询实盘文件。

## 5. UI 与交互

- 全局顶部固定账户条，真实与模拟使用文字和不同底色，不仅依赖颜色。
- 模拟固定展示：独立模拟账户、无需实名、虚拟资金；手机端仍显示资金提示。
- 切换入口不藏在个人设置，不因交易请求未完成而禁用；仅在本次切换初始化时防止重复点击。
- REAL -> DEMO 先握手检查 environment、UID 和会话未变化，成功才保存选择；失败保持原账户。
- DEMO -> REAL 直接切换，不强制认证才能离开模拟；真实下单由真实服务继续校验资格。
- 优先保持安全的交易/资产等主页面；包含记录 ID、弹窗或不安全参数的上下文回到主页。旧表单不跨账户携带。
- PC 沿用完整交易台和用户中心；手机沿用原有页面与底部导航，不再跳转功能缩水的练习页。
- 按钮支持键盘聚焦；失败消息使用 role=alert；充值页面额外禁止真实汇款的文案。
- 新账户和切换文案登记日语；现有其他语言继续使用项目默认回退机制。不声称所有语言经过人工语言审核。

## 6. 部署、回滚与运维

本次完成源码、独立环境配置与本地测试；未启动生产模拟容器，未改写现有实盘数据。

1. 在受控环境准备独立 DEMO_MYSQL_ROOT_PASSWORD、DEMO_MYSQL_PASSWORD、DEMO_JWT_SECRET；不要复用实盘密码，不提交 secrets。
2. 校验：`docker compose -f compose.yaml -f compose.demo.yaml config --quiet`。
3. 经上线流程批准后部署：`docker compose -f compose.yaml -f compose.demo.yaml up -d --build backend demo-backend pc mobile`。会重建实盘 backend 以提供只读身份/目录端点，应安排发布窗口。
4. 本地开发：真实端口 8080，模拟端口 8081（SERVER_PORT）；模拟设置独立 MySQL、Redis、工作目录。Vite 已配置 /demo-api 和 /demo-uploads 代理。
5. 验收：未实名测试用户握手成功、三个虚拟钱包、所有类别下单、切回实盘余额不变、服务断开无实盘回退。再做双 MySQL/Redis 环境下并发及长时间自动结算验收。
6. 回滚：停止 demo-backend，恢复前端版本/入口；保留模拟卷供审计，禁止删除实盘表或整库回滚。已有已提交模拟订单可能仍需恢复服务处理。
7. 代码改前备份位于 rollback/demo-full-account-20260929。仓库有并行修改，恢复时逐文件逐段核对，不要整体覆盖其他工作。

建议上线监控（目标，并非本次已测性能）：开户失败率、目录同步失败、身份验证耗时、跨环境拒绝次数、虚拟余额与冻结一致性、结算积压、前端切换失败率。任何模式误路由立即报警并停止相关入口；资金不相等先停止该账户写入再核对凭据。
