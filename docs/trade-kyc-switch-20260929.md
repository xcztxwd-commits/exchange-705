# 未实名不可交易开关

后台入口：系统设置 → 风控配置 → 未实名不可交易，点击“保存配置”生效。

配置键为 `trade.kyc.required`，按租户存储，接受字符串 `true` / `false`，遵守现有总控锁定和后台权限。未配置时默认开启，避免升级后静默解除原有实名门槛。无数据库迁移。

## 行为

- 开启：最新基础实名记录必须是 `APPROVED`。未提交、待审核、驳回均不能交易，体验金也不能绕过。
- 移动端自动进入 `/verification`；PC 自动打开用户中心的实名认证页；同时弹出实名提示，不再要求先确认才导航。
- 服务端统一阻止 `/api/trade/**` 的写操作（含合约、期权下单、手动平仓、撤单、修改止盈止损）以及理财申购和赎回。返回 HTTP 403、`KYC_REQUIRED`，两端统一处理，保留登录状态，不重放订单。
- 行情、订单历史、实名提交不受影响。自动结算仍执行；限价撮合也遵循开关。
- 关闭：只解除交易实名门槛，提现和贷款的原有独立身份要求不变。正常余额、参数和租户功能授权校验仍执行。
- 独立模拟环境沿用原有模拟身份豁免，不改变真实身份状态。

本说明替代旧交易实名说明中“体验金豁免、取消导航、手动退出不受门槛影响”的对应行为。开启期间未实名用户的手动退出操作也被拦截，管理员应注意已有持仓用户的实名审核。

## 验证

- `mvn -q -f exchange-backend/pom.xml -Dtest=TradeKycSwitchTest test`：开关默认值、即时切换、最新审核状态、有体验金仍拒绝、关闭后提现仍要求实名、写入拦截、配置值校验。
- 移动端、PC、后台均通过 `npm run build`（含 TypeScript 检查），保留现有大包警告。
- 启动移动端 5293 / PC 5295 后运行 `node exchange-frontend/tests/tradeKycSwitch.browser.cjs`。使用模拟 API，验证真实页面按钮、三个拒绝状态、两类交易、自动跳转和弹窗、关闭放行、已审核放行、服务端拒绝统一导航及无重复下单。Browser plugin not available，复用仓库 Playwright。
- 浏览器证据：`reports/trade-kyc-switch-20260929/`。未执行生产环境交易，也未部署。
