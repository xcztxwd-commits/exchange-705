# 新用户 ID 从 752911 开始

旧用户 ID、外键和已签发会话不变。所有租户共用数据库持久化分配器，从 752911 递增；已占用号码自动跳过。分配器通过 Hibernate 的独立事务和数据库行锁处理并发及重启，失败或回滚的注册可能留下号码空洞，不回收号码。

现有用户 ID 已超过 7000000，因此不能通过降低 MySQL AUTO_INCREMENT 实现此要求。注册和其他通过 UserAccount 持久化的新用户统一使用新的分配器。手工 SQL 导入不是注册流程，应停写后导入，避免与分配器同时分配相同号码。

## 发布

1. 备份数据库；停止全部后端实例，避免旧版自增分配器与新版混跑。
2. 在现有多租户数据库执行 `exchange-backend/src/main/resources/db/migration/V2026093005__user_id_sequence.sql`。全新库使用更新后的多租户迁移清单。该 SQL 可重跑，不重置已分配号码。
3. 部署新后端，按现有多租户发布流程完成隔离验收与激活；应用 epoch 为 2026093005。不要修改 Hibernate 默认的 `hibernate.id.generator.stored_last_used=true`。
4. 恢复注册，检查首个未占用的新号码为 752911，并验证后续递增、旧用户登录和关联资产不变。

不修改旧用户，不删除数据。恢复备份代码只能在停止全部后端后操作；保留 `user_id_sequence` 分配状态，不将 `next_val` 改回 752910。若退回应用 epoch 更低的旧发布，需要按既有发布门禁流程处理，不要直接降低门禁或删除迁移记录。

## 回归检查

`mvn -Dtest=UserIdGeneratorTest test` 验证起始值、旧 ID 保留、跨租户占用跳过、并发唯一、回滚不复用和后端重启续号。
