# 交易前实名认证门槛（2026-09-29）

## 已实现

注册、登录和浏览行情不代表可以交易。移动端与 PC 的合约买卖（市价、限价）、期限/期权买涨买跌均先检查基础实名。

- 未提交：提示先完成实名认证，确认进入实名页面，取消留在原页。
- 审核中：提示审核中，通过后才可交易。
- 驳回：提示修改资料后重新提交。
- 已通过：继续原有余额、行情、参数校验，不影响原有交易限制。
- 状态查询失败：阻止下单并提示重试，不默认放行。
- 后台审核通过后，页面重新激活或再次点击下单都会刷新状态，不要求重新登录。
- 审核通过、返回页面、关闭提示均不会自动重发用户之前点击的订单。

移动端确认前往 `/verification`；PC 打开用户中心的实名认证页。注册后即使余额为零，未实名用户仍能点击买卖按钮并看到实名提示，不会因余额校验先禁用按钮而失去认证入口。

## 唯一身份来源与后台

基础身份继续使用 `kyc_record` 的最新申请，只有 `APPROVED` 放行。`user_account.kycStatus` 缓存标志、前端缓存、贷款资料通过状态均不能替代真实审核记录。

后台继续在“实名审核”（`/kyc-review`，API `/api/admin/kyc/{id}/approve`）批准基础实名；“贷款资料审核”仅负责贷款补充资料，不授予交易资格。该审核通过链路已通过真实 Controller + H2 集成测试。本次不新增第三套实名或交易审核模块，也不修改管理员历史手工订单工具。

此前“一套基础实名身份 + 一套贷款补充资料”的拆分保留，贷款原有错误提示和资料审核规则不变。

## 服务端兜底

- `ContractOrderService.createOrder`、`OptionOrderService.createOrder` 在订单保存、冻结资金前统一调用 `KycIdentityService.requireApproved`。
- 不满足条件返回 HTTP 403、`errorCode: KYC_REQUIRED`、`kycStatus`。两端保留业务错误码并显示认证提示，不将其误判为登录失效。
- `/api/kyc/status` 返回基于审核记录计算的 `kycStatus`、`canTrade`，使用 `Cache-Control: no-store`。
- 限价撮合的新旧订单分支均检查实名，不通过则维持待成交，可撤单；已有待成交委托在用户通过实名后仍按原撮合规则处理。这与不自动重发失败的点击是两回事。
- 撤单、已有持仓平仓、止盈止损、到期期权结算不附加实名要求，避免影响退出与资金释放。
- 页面卸载和账号切换不会让旧账号的异步审核结果授权新账号。
