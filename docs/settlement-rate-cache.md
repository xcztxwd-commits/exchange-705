# 可配置结算汇率缓存

后台「系统设置 → 结算汇率」设置更新间隔，单位为整数小时，范围 1–168，默认 8。保存到现有系统配置 `market.conversion.cache-hours`，无需数据库迁移。

非 USD/USDT 结算汇率以源、源分类、源代码为键存入 Redis：`market:conversion:<source>:<category>:<code>`。缓存期间固定使用同一源价格，前台保证金与后端开仓、平仓共享该汇率。USD/USDT 维持现有 1:1 结算约定。便士等小单位在读取缓存后按既有比例换算。

有效期从源报价时间开始计算，避免给陈旧数据重新计时。Lua 脚本原子读取或更新，保障并发请求使用同一快照。后台时长修改后，下次读取按原始报价时间重新计算到期时间；不会因读取而滑动续期。已有快照可在上游中断或服务重启后继续使用，到期后没有有效候选汇率则不可结算；Redis 故障时也不临时换用另一汇率。

现有行情采集继续运行，快照仅在到期后更新。后台元数据任务每 30 秒预热所需汇率，页面与交易读取也会触发到期刷新。候选必须是最近 60 秒收到且源有效的正数报价，源时间不得超过配置有效期。此策略仅调整结算汇率，不放宽品种成交价的实时有效期。

验证：`docker/test-settlement-cache.py` 在隔离 Redis 检查固定值、TTL、故障/重启复用、时长变更及过期拒绝；后端 `QuoteCurrencyConversionTest` 检查配置边界、有效期和小单位换算；`exchange-admin/tests/settlementSettings.browser.cjs` 使用独立浏览器与模拟接口验证默认值、修改保存和重载。浏览器测试不会更改运行数据库配置。

## 币种预缓存

后台支持多选或输入 ISO 三位法定货币代码，最多 30 种，USD 为固定基准。配置键为 `market.conversion.currencies`，缺省值为 `USD,EUR,JPY,GBP,CNY,CHF,AUD,CAD,HKD,SGD`；人民币与新加坡元已包含，不重复添加。主流币种按 [BIS 2025 外汇成交量统计](https://www.bis.org/statistics/rpfx25_fx_annex.pdf) 的前十币种选取。

所有法币统一按「1 单位币种 = 多少美元」保存。USD 固定为 1，不请求外部汇率。选中的其余币种经 Yahoo 外汇来源订阅并预热 Redis，与结算时间设置共用缓存逻辑。新增、移除预选币种在下一轮元数据刷新（最多约 30 秒）应用。交易和充值业务已依赖的币种继续自动订阅、缓存；取消未使用币种后停止预热，旧快照按原有效期自然过期。币种代码有效不代表上游一定提供该品种，缺失源数据时不生成虚假汇率。

2026-09-22 币种配置验证：127 项后端测试中 123 项通过、4 项环境条件测试跳过；独立浏览器测试通过币种新增、持久化读取和恢复默认；隔离 Redis 缓存脚本测试通过。
