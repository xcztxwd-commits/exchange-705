# 多租户下一阶段差距分析：功能、业务闭环与验收

日期：2026-09-29。范围：当前工作区源码、原始多租户需求、后续实现文档和已有测试证据。本文是源码复核及实施设计，不是新一轮全量测试报告，也不是上线批准。

## 1. 结论与对前次答复的修正

**当前不是“所有功能做完，只差测试”。也不能把未通过测试的部分全部算作功能没实现。** 已有身份、租户隔离、控制台、业务授权、资金事务、在线统计、客服留存等主体实现，但仍存在具体功能缺口、跨功能规则冲突、迁移工具生产路径缺口和同版本验收缺口。

前次提到的“表格偏好”不是唯一未闭环项。本次进一步确认：域名切换尚不是设计要求的先验证后切换；客服监管缺时间筛选；大会话导出/归档与恢复存在能力边界；新增活动素材表未纳入租户清单；后续 KYC 限制与原有资金退出要求需要明确合并规则。

保证完成应依靠逐项需求映射和验收闸门，不能依靠完成百分比或“页面能打开”。本轮不改业务代码、不操作数据库、不启用清理、不部署，也不自动创建新会话。

## 4. 具体未实现或未闭环事项

编号在设计及执行文件中保持一致。P0表示发布硬前置，不表示已发现线上P0事故。状态分为：代码缺口、整合缺口、规则待定、验收缺口、运营前置。

### G01 — 当前版本与新增代码的隔离登记（P0，整合缺口）

新增 ActivityMaterial/Repository/Controller、TradeKycGate 未登记，多个原敏感文件已变化。V05 建了 activity_material，但清单未分类，DDL只有tenant字段及索引，没有到tenant表的外键；实体本身已继承租户owner并使用租户persister，不能因此称整个素材库毫无隔离。

需要把实体、表分类、数据库约束、查询、素材图片引用、权限、软删、审计要求和迁移顺序作为同一个变更审核。当前迁移入口会glob读取V20260929*.sql，所以V05不是“不会执行”，而是旧的V03/V04成功演练不再覆盖当前脚本集合。核对已有库升级与旧库首次迁移两条路径，不能简单重跑旧DDL。

### G02 — 停止新增、KYC和资金退出组合规则（P0，规则待定及验收缺口）

原多租户方案要求关闭模块后保留存量平仓、赎回、还款等必要退出。后来KYC文档明确要求未实名时拦截手动平仓、撤单、止盈止损修改及理财赎回，TradeKycGate确实覆盖这些写操作。

这不是可以直接判定为“新代码写错”的问题：后续要求可能有意改变旧行为。必须形成一张明确的状态/命令权限表，决定未实名存量持仓的受控处理入口；不能为了旧测试通过删除KYC，也不能以关闭功能为理由让存量资金永远没有退出路径。活动文档还记录当前44项活动回归有7项因KYC旧预期失败，与19:23的全量数字是不同运行。

### G03 — 表格偏好双身份整合（P1，代码缺口）

AdminTable直接读取普通后台Pinia和admin API；独立总控入口没有同一store。新增共享组件和总控表格尚未接入。需要普通管理员/代理、总控租户访问、独立总控三种偏好身份，避免把总控凭据传给普通后台客户端。偏好永远不能赋予列权限。

### G04 — 域名预备、验证、原子切换（P1，代码缺口）

TenantManagementService.update先退役旧域，再把frontendHost改为新域并置维护/未验证；verifyDomain之后才验证当前域名。当前是“切换后停用等待验证”，不是原设计的“新域准备并验证成功后原子切换”。

需要候选域名/验证状态/唯一占用机制，失败不影响旧活跃域名；激活事务保证一租户一个活跃域名，并发占用不重复；旧域拒绝、缓存及旧页面写入失效、退役域复用审核均要测试。不要求新增微服务或动态DNS供应商集成。

### G05 — 客服监管时间检索（P1，代码缺口）

设计要求按租户、用户、客服、时间检索。当前ControlReadController.conversations及ChatSupervision只有用户、客服、分页，没有时间条件。应增加明确UTC/时区语义的起止时间、范围校验、数据库索引及前端筛选，保持只读和审计，不更新未读状态。

### G06 — 大会话导出、留存推进和恢复（P1，代码/运营闭环缺口）

- 同步证据导出超过2000条消息或32MiB附件即拒绝；提示使用受控归档，但现有工具只有initialize/verify，未提供完整的大会话导出/回灌工作流。
- 自动清理固定选择最前100个候选；超过10000条消息或32MiB附件则保留并continue。**从代码可推导**：若最前100个都超限，之后的小会话可能长期得不到处理。须先用合成库复现，不能写成线上已经发生。
- retention_archive.verify验证归属、文件摘要、附件bytes；不是恢复至数据库、完整消息链复核及关系重建的证明。`.retention-restore-verified`标记不能替代真实恢复验收。

需有界流式导出、任务状态与断点、失败/超限不阻塞其他候选、完整哈希链校验、只恢复到隔离新库的命令及证据。保持默认清理关闭；不通过增大内存或删除超限会话规避。

### G07 — 历史数据和文件的受控正式处理入口（P0，工具闭环及运营前置）

孤儿与私有文件工具的apply故意只允许测试实例；正式入口尚未提供。已有合成演练不是“没有工具”，也不等于“生产只需按按钮”。

必须有明确目标身份、停写证据、精确计划hash、备份/独立恢复、审批、逐行归档、批次收据、失败可续跑和数据不变量校验的正式编排。不能直接删掉fixture保护。旧盘点中的孤儿/文件缺失/归属歧义仅是历史快照，正式执行前重盘；不凭空补用户或猜归属。

### G08 — 新租户可经营配置与外部通道（P1，配置闭环；短信另需范围决策）

safe-v1是安全空模板，不是营业配置。仍需已审核的币种/产品/期限/费率/收款方式、邮件出站白名单、域名/TLS、初始负责人及真实/模拟配置清单，形成“创建到首次业务成功”的操作路径。

现有认证通道是email；本轮检索及出站补充文档均未发现实际租户SMS发送器。原需求提到短信独立配置：若包括实际短信发送，则配置、加密密钥、供应商适配、限流/验证码隔离、回执和失败行为尚需实现；不能把任意config键可保存算完成。供应商未指定时先完成本地sink和契约，真实供应商验收标blocked。手机号跨租户可重复本身不等于必须支持手机号登录，不能擅自扩大需求。

现有工程没有实际webhook发送器，且原需求未明确要求该产品能力，不把它当作必做缺口。邮件可靠outbox属于可选增强；必须测试现有发送成功/持久化失败的行为，但不无依据强制引入消息队列。

### G09 — 运营异常可发现、可处理、可复核（P1，部分实现与运行闭环缺口）

TenantJobRunner记录错误后继续其他租户，下次tick重试；这是容错基础，不是完整运维闭环。已检查总控路由没有设计总览中的“待处理异常”汇总、处理记录与恢复证据入口。

应复用日志/指标或最小异常登记，实现任务持续失败、留存跳过、审计失败、配置缺失和迁移阻断的可见状态。先做有限告警和人工处理手册，不引入通用工作流平台。人工重跑也必须有租户范围和幂等保护。

### G10 — 旧夹具与新规则测试兼容（P0，测试缺口）

上一轮尚有26个失败套件，主要类别为缺TenantContext、TenantPolicyService依赖、H2市场schema、客服Bean，以及需要进一步归因的权限断言。必须逐套分类与修复；并发和动态测试分别覆盖执行线程，不能靠全局默认租户兜底。

最新KYC/活动代码可能改变失败分布，应在冻结后重跑，不能把213个errors原样认定为当前数量。MySQL IT、条件跳过和浏览器mock单列，不能宣称mvn test自动包含所有测试。

### G11 — ORM/权限/资金/模拟/任务全链同版本验收（P0，验收缺口）

复用已有MySQL探针和回归，不重做框架。覆盖新表及全部私有读写类型、显式bulk/native、锁、缓存、异步回收；资金要验证真实API身份到提交/审计的整链，而不是仅调用服务。模拟服务实时授权及停用/失联行为、行情广播/缓存/Redis/任务租户边界必须在双实例下核验。

### G12 — 四端集成、容量与发布恢复（P0，验收及部署闭环缺口）

冻结同一后端jar、四入口资源、DDL和配置版本，验证实际Nginx/TLS、PC/移动视口、后台/总控多标签、私有文件/音频、约100并发及故障恢复。历史非租户发布或旧隔离jar通过不能替代。发布批准、真实数据治理、存量任务接续和新写入后回滚边界仍保留。

## 7. 使用边界

“开发闭环”“隔离验收通过”“获准生产上线”“已发布并观察稳定”是四个不同结论。新会话必须逐级交付，不能用设计文档或局部测试承诺零风险、完整上线、所有预期均已实现。未确认的KYC优先级和短信范围明确列为决策项，其余已确认功能不重复询问。
