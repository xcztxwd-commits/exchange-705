# 模拟账户：产品、隔离、架构与交付方案

## 1. 决策与本次交付边界

登录身份共用，资金账本独立。用户无需实名认证即可进入模拟账户；切换到真实账户不改变其实名认证状态，也不获得真实交易权限。模拟收益永远不能兑换、转入或提现。

本次实际实现的是**可持久化的独立模拟现货练习账户**，不是在现有钱包上加一个显示开关。支持已经启用、行情来源类别为 Crypto、计价币为 USDT 的品种：市价买入、整笔卖出、持仓估值、净盈亏、历史、流水、重置，以及移动端和 PC 端切换入口。默认赠送 100,000 虚拟 USDT。

**没有把现有合约、期权、外汇、理财和借贷系统直接改成模拟模式。**这些产品涉及不同的保证金、换汇、期限结算、强平规则；不能用现货算法冒充。下文给出扩展路径，未交付项不表示已完成。

当前仓库已有“本站仅用于模拟测试与功能演示”的声明。“真实账户”在本文和切换按钮中指现有业务账户，不表示该系统已经具备真实交易所订单路由或可以生产运营。原有演示声明不移除。

## 2. 用户与权限矩阵

| 状态 | 模拟账户 | 现有真实业务账户 |
| --- | --- | --- |
| 未登录 | 路由要求登录，API 继续受 ROLE_USER 保护 | 原有规则 |
| 已登录、未实名/审核中/被拒绝 | 可使用模拟现货，不访问 KYC 接口 | 真实交易仍通过现有服务端 KYC 检查 |
| 已实名 | 同样可练习，资金不合并 | 原有规则 |
| 冻结/封禁/不存在 | 服务端拒绝模拟读写 | 原有规则 |
| 管理员/代理身份令牌 | 不能通过 USER API 访问模拟账本 | 原有后台权限体系 |

认证身份只来自 Spring Security 的 Authentication；不接收客户端 userId 来决定所有者。前端按钮禁用不是鉴权。

## 3. 功能规则

### 开通与赠金

- 用户点击“切换模拟账户”进入 `/demo`，加载页自动幂等开通。
- 创建 `demo_account` 与 SEED 流水处于同一事务；刷新、多标签同时开通不会重复赠金。
- 不自动为全部老用户建表行，不修改注册、实名与真实钱包逻辑。
- 开通失败显示错误与重试，不用本地假余额兜底。

### 交易

- 仅 USDT 计价加密现货、全额资金买入；不借币、不卖空、不加杠杆。
- 输入为买入名义金额，10 至 100,000 USDT，最多两位小数；余额还需覆盖手续费。
- 买入和卖出各收 0.1% 虚拟手续费；服务端 BigDecimal 为唯一结算依据。
- 数量 = 金额 / 成交价，向下保留 16 位；费用和现金保留 8 位；超过数据库数量精度明确拒绝。
- 买入扣款 = 金额 + 买入费；卖出入账 = 数量 × 卖出价 − 卖出费。
- 净盈亏 = 卖出入账 − 买入金额 − 买入费。持仓展示按预估卖出费用计净值。
- 每笔买入独立成仓，一次完整卖出；最多同时 50 笔持仓。
- 市价下单同步完成，无虚构的挂单、撮合深度或排队状态。参考价不是锁价承诺。
- 无成交量约束、滑点模型和真实市场冲击，UI 提醒模拟收益不代表真实收益。

### 资金重置

- 用户须先卖出所有持仓，再确认重置至 100,000 USDT。
- 两次成功重置至少间隔 24 小时，非客户端计时判定。
- 重置增加 generation，保留历史订单与流水；不删除任何历史。
- RESET 流水记录差额而非伪造充值。旧 generation 的延迟请求不能作用于新一轮账户。
- 重复同一重置请求返回已有结果，不重复加款；新请求受冷却限制。

### 切换

- 使用独立 URL 与独立组件树，不共享真实交易组件中的余额、订单或下单表单。
- 全局账户条持续显示当前模式；模拟条使用靛蓝色并显示“虚拟资金、不可提现”。
- 进入模拟不要求实名，不弹充值提示；返回真实需确认，提示实名要求及资金不可转入。
- 切换不自动卖出持仓、不自动提交表单、不转移资金。
- 模拟写请求处理中禁止离开当前路由，刷新/关闭页提示未完成请求。
- 模式是标签页的路由上下文，不保存成全用户可变“当前账户”字段。因此一个标签页切换不会偷偷改变另一个标签页的下单目标。
- 刷新保留当前 URL；换用户重挂载页面、清除展示数据。写操作重试键按用户隔离。

## 4. 架构

```text
同一个登录身份 / JWT / USER 权限
   ├── 现有真实业务页面 -> 原有业务 API -> 原有服务与账本（KYC 不变）
   └── /demo 页面 -> /api/demo/* -> DemoTradingService
                                    ├── demo_account
                                    ├── demo_order
                                    └── demo_ledger
                       只读行情 -> ForexQuoteMarketService.getPrice(code, Crypto)
```

采用单体内独立业务模块，复用已有 Spring 事务、JPA、认证和行情缓存，不增加消息队列、微服务或前端依赖。初版的复杂度花在账本一致性和边界上，而不是部署拓扑。

### 数据隔离

1. **资金层**：只有 demo 表能被 DemoTradingService 写入。该服务不依赖 AssetAccountRepository、真实订单仓储、充值、提现、代理返佣或真实结算服务。
2. **订单层**：独立随机 UUID，所有读写带 userId 条件；真实任务只扫描其原有订单表，不能结算模拟订单。
3. **统计层**：现有真实报表、代理业绩、资产权益不会读取 demo 表。今后新增 SQL/ETL 必须显式分类，不做两个账本的无条件 UNION。
4. **请求层**：模拟请求附 `X-Account-Mode: DEMO`；后端拦截模拟上下文对真实业务的误访问，返回 409。
5. **白名单**：DEMO 上下文仅允许 `/api/demo/*`、只读行情命名空间和心跳。头部不是权限凭证；去掉头部也不能绕过真实业务 KYC 或 USER 权限。
6. **缓存层**：模拟账户响应设置 `Cache-Control: no-store`；当前实现不缓存模拟余额、持仓或结果。行情缓存可共用，因为无用户资金。
7. **会话层**：保留请求发起时 token，旧用户异步响应不能写入新用户 UI。

当前是**同库分表、服务分离的逻辑隔离**，不是物理数据库隔离。数据库管理员仍可读两类表。需要更强隔离时，将 demo 表迁入独立 schema/连接池/受限数据库用户，再拆服务；不要把“分表”宣传成物理隔离。

### 行情隔离

- 模拟取原始 Crypto 行情，不走 `freshPrice` 控盘结果、不用管理员手动历史订单或随机价格路径。
- 同时校验行情数值、源时间、抓取时间、可用标记；超过 60 秒或断源不成交。
- 买入时保存 marketCode，后续卖出仍使用该来源标识，不随显示符号重命名而切换来源。
- 持仓存在缺失行情时，总权益与未实现盈亏显示“—”，不填零、不保留过期值冒充最新价。
- 独立页不复用可能带控盘修正的 K 线图；如补充图表，必须提供明确的原始行情图表端点，保持显示与执行一致。

### 并发与幂等

- 在事务内使用现有用户行 `SELECT ... FOR UPDATE`，串行化同一用户的模拟开通、买入、卖出和重置。
- 数据库锁跨 JVM 生效，不使用进程内锁；不同用户可以并行。
- `(user_id, request_key)` 数据库唯一约束阻止重复买入。相同键不同参数拒绝。
- 已卖出订单重试不再次入账。客户端不给卖出价格，服务端自行报价。
- 现金、订单状态、流水一起提交或一起回滚；流水失败不能留下扣款成功的半笔订单。
- 前端 sessionStorage 保留用户、操作与完整参数对应的请求键；响应丢失后同参数重试沿用旧键。
- 所有页面读取也短暂使用该用户锁获得一致账本快照；没有锁内外部网络请求，只读取现有行情快照。
- `ponytail` 边界：目前读操作也锁用户行。若真实观测显示热点用户/心跳争用，应改为 demo 账户行锁加单独开通幂等方案，并将读取改为一致性只读事务，而不是现在引入分布式锁。

## 5. API 与数据

| 方法 | 路径（统一 `/api` 前缀） | 行为 |
| --- | --- | --- |
| POST | `/demo/account` | 幂等开通，返回账户 |
| GET | `/demo/account` | 现金、持仓、权益、费用率、服务端时间 |
| GET | `/demo/instruments` | 受支持品种及原始行情可用状态 |
| POST | `/demo/orders` | `requestKey, generation, symbol, amount` |
| POST | `/demo/orders/{id}/close` | `generation`；整笔卖出 |
| POST | `/demo/reset` | `requestKey, generation` |
| GET | `/demo/orders?page=0` | 已关闭订单，20 条/页 |
| GET | `/demo/ledger?page=0` | 全轮次流水，20 条/页 |

订单含用户、轮次、源代码、买卖价格、数量、费用、净盈亏、状态与时间。账本含用户、轮次、关联订单、事件类型、现金变动、变动后余额与时间。时间使用 Instant；页面按用户设备时区显示。

未在 GET 中创建余额。请求体上的服务端校验拒绝空金额、负数、越界、非法精度和缺少代际字段。未知订单与他人订单统一报“不存在”。

## 6. 页面 UI 与体验

```text
账户模式条：模拟账户 / 虚拟资金不可提现           [切换真实账户]
先练习，再开始。                                 SIMULATION
风险说明：仅模拟、不入交易所、不可充值提现、收益不可预测

[模拟总资产]           [可用虚拟资金]           [未实现盈亏]

[模拟买入]                    [练习记录：持仓 | 历史 | 资金流水]
  品种下拉                      空态：从第一笔练习开始
  参考价与行情状态                有仓：品种 / 数量 / 盈亏 / 全部卖出
  金额及快捷金额                  历史：时间 / 品种 / 净盈亏 / 轮次
  手续费、预估扣款                分页、刷新与明确错误
  [使用虚拟资金买入]              重新开始 / 重置说明 / [重置资金]

三步指引：买入练习 / 观察并卖出 / 准备好后再切真实
```

- PC 双栏，移动端单栏；资产卡使用紧凑三列，小于 370px 时单列。
- 模拟采用靛蓝，不与原有买卖涨跌色混淆；模式信息用文字而非仅颜色表达。
- 输入原生 label、键盘 focus、至少 40px 按钮、状态 aria-live、错误 alert。
- 买入、卖出与重置使用原生确认框，保留浏览器键盘和焦点行为。
- 首屏给解释和小额快捷选项，不做强制教程；没有强迫用户实名认证的模拟流程。
- 使用现有 locale.text 提供中文/英文及已有翻译映射；新增文案其余语言翻译仍需母语审校，不承诺所有语言完整。
- 网络失败显示“结果未确认”的既有错误处理；不擅自生成新交易键重复扣款。
- 后台标签暂停 5 秒轮询，恢复后刷新；无行情时按钮禁用、估值为空，真实资金始终不显示在模拟页。

## 7. 运营、风控与扩展设计（未全部实现）

### 上线前必须确认

- 模拟默认本金和费用是否最终采用 100,000 / 0.1%；目前是版本内常量，不允许用户或客户端调整。
- 交易品种配置实际包含 Crypto + USDT；空配置显示空态而不是静默套用不兼容产品。
- Nginx/CDN 对账户 API 不缓存；用户认证与接口限流沿用现有防护并进行容量核查。
- 用户删除/合规数据清理任务要把 demo 表纳入其策略，不能自行删除真实审计数据。
- 如实际产品要对外开展真实交易，必须单独审查合规、托管、订单路由和市场数据授权；本功能没有解决这些问题。

### 建议监控与验收指标

- 模拟开通成功率、重复赠金数（必须为零）、重复卖出入账数（必须为零）。
- 负现金数（必须为零）、账本末余额与账户现金差异（必须为零）。
- 首笔练习转化、次日练习留存、模拟至实名流程到达率，不能用收益率鼓励用户增加风险。
- 源行情过期拒单、锁等待、API P95 延迟、HTTP 409 模式误用次数。
- 生产限流按 userId 与 IP 双维度实施；本次没有另外建立专用限流/监控平台。

### 后续扩展顺序

1. **体验增强**：历史明细、部分卖出、原始行情 K 线、模式切换回到原品种、完整母语文案、移动端独立路由导航。
2. **交易一致性增强**：可配置滑点/盘口/成交量约束、限价单状态机；报价中断时明确挂起而非自动制造成交。
3. **合约与外汇**：抽取不访问仓储的纯计算规则，分别以真实/模拟仓储调用；独立保证金、资金费、强平与止盈止损任务。不可用一套现货数量规则处理外汇手数。
4. **期权**：独立 demo 到期队列与结果账本，所有事件携带环境与账户标识，不共用真实结算消费者。
5. **运营后台**：独立只读模拟统计与审计权限；任何赠金操作均生成模拟流水，不计代理收入。不得复用真实人工订单入口。
6. **物理隔离**：根据负载/合规需要拆 schema 和连接池；市场数据可保持只读共享，禁止跨环境资金 RPC。

充值、提现、跨环境划转、借贷与理财购买不属于模拟练习功能，默认保持禁止，而不是做虚假“提现成功”的演示。

## 8. 部署、验证与回滚

- 新表脚本：`exchange-backend/src/main/resources/db/migration/create_demo_accounts.sql`。项目当前并未配置自动 Flyway，不能仅放置脚本就声称已迁移；开发 ddl-auto=update 与生产人工迁移要区分。
- 本次没有连接或迁移生产数据库，没有重启生产服务。
- 发布顺序：备份数据库；在隔离预发执行新表脚本；部署后端；验证登录、无实名开通与交易；再发布两个前端。
- 新模块不改既有钱包/订单表，不需回填真实用户资产。
- 回滚顺序：先撤下前端入口/恢复对应文件，再撤下 demo API 新代码；**保留三张 demo 表**供审计与恢复，不删除真实或模拟历史。
- 修改前的 6 个集成文件保存在 `rollback/demo-account-20260929/` 下，恢复时仅选择本功能文件，不覆盖其他任务后续修改。其余本次新建文件按清单撤下。
- 单元测试：`mvn -Dtest=DemoTradingTest test`。
- 持久化事务/并发测试：`mvn -Dtest=DemoPersistenceTest test`，使用内存 H2，绝不使用 application.yml 的真实数据库。
- 两个前端分别执行 `npm run build`；浏览器用模拟 API 数据验证交互，不把 mock UI 测试当成真实 API 端到端验收。
- 仍需在预发 MySQL 与真实配置行情下验证迁移、事务锁、JWT 认证全链路、禁用状态、请求限流与重启恢复，完成后才能宣称生产可用。
