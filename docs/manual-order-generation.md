# 手动模拟单：约束联动与一键生成

## 需求解释（2026-09-28）

这是既有带手动标记的模拟单生成器，不是真实交易预测。选择用户、品种和时区后，开/平仓分钟、方向可独立填写，填写后严格保持。杠杆作为数值目标允许上下 5% 调整；用户、品种、时区和开关不是百分比目标。目标手数、仓位比例、目标净收益、目标平仓价可同时填写；每项只在明确输入后才成为生成目标，未填写项由计算结果回填显示。清空某项只释放该项，不清除其他目标。

生成只查询历史行情、计算和预览，不创建订单、不改钱包、不改权益。仍需点击既有确认创建按钮，沿用原有权限、净收益、开关联动、事务及手动标签。

杠杆、手数、仓位比例、净收益、目标平仓价均采用相对误差：abs(实际－目标)/abs(目标) <= 5%，包含边界；负收益同样处理。净收益目标为 0 必须实际为 0，不把百分比除零。任一目标超界即拒绝，不能悄悄改目标或自动创建。目标平仓价与所选分钟 K 线 open 对比，不改历史价格、手续费或利润字段凑数。

已填写的目标不被生成器覆盖；结果中另列实际值及偏差。目标手数可输入高精度值，例如 `28.6757379`；实际成交数量按品种配置的数量步长和最小数量取值；旧规格默认 `0.01`。候选优先降低各项偏差中的最大值，再兼顾持仓时长、仓位和杠杆。条件冲突时明确报错。无法计算比例的非正余额不允许填写比例，仍允许其他输入。

## 搜索与真实性偏好

未填写平仓分钟时，先在最近七天内找**最新有有效行情及换算率的已结束分钟**，将它固定为平仓分钟；随后只在该分钟之前最多七天找开仓分钟。只填目标平仓价时，也固定这个最新平仓分钟，自动寻找开仓时间、手数及仓位，目标价格容差 ±5%；最新实际价格超界则提示，无权伪造价格或改用更早的平仓分钟。若最近七天无平仓数据、或此前七天无符合条件的开仓分钟，给出明确提示。用户填写平仓时间时仍严格固定该分钟；两端都填写时直接验证。生成接口统一只使用已结束分钟。范围有界且在结果中明示，不声称穷尽全部历史。仅使用系统现有历史行情链路返回的有效分钟 open 及对应换算率，缺数据不造价；该链路可能包含系统已有的历史价格配置，不能把结果宣称为未经处理的外部市场成交记录。

候选优先小时级持仓（约 2–12 小时），兼顾 1–3 天；几分钟持仓给极高惩罚，不设不可突破的统一最小时长。用户固定的时间必须尊重；短时数据只能作为低优先级候选，并给出提示。自然仓位和适中杠杆有更高权重，但不禁止已允许的超额仓位。少量随机扰动让同样约束下有变化，不能以随机替代收益校验。最终必须再次走权威预览，复查约束与误差。

## 实施边界

增加独立、有界的纯计算候选选择器；行情批量读取复用现有窗口缓存；后台新增 generate API 后接回原 preview/create。UI 固定条件与显示计算分开，生成过程中防止旧请求覆盖新表单。无需数据库迁移，不改普通订单、钱包和权益归集业务。

## 验收

后端同时收到手数、比例、杠杆和目标收益时，按真实价格、费率和 `0.01` 手数步长寻找使数值目标均在 ±5% 内的候选；固定时间、方向不变，杠杆在目标 ±5% 内按 0.01 精度搜索。截图场景输入理想手数 `28.6757379` 应生成 `28.68` 手；当前 USD/JPY 的 USD 保证金口径下，68% 目标的实际比例约为 `68.01010534%`。普通手动预览仍按精确手数与 `0.01` 个百分点比例差检查；一键生成的预览按新容差检查。

覆盖仅净收益、收益加开仓时间、只固定平仓、手数/比例目标与固定方向及杠杆目标的组合冲突；正负/零目标、5%边界和超界；真实时长偏好与短时回退；分钟/时区/未来校验；后台构建和浏览器生成后确认流程。算法测试不代替实际生成 API 与浏览器验证。结果必须保留手动来源，未实际运行的测试不得写成通过。

## 2026-09-29 补充

杠杆候选包含目标、上下边界，以及按仓位上下界反算的相邻两档，最终统一复验全部目标，输入目标不被覆盖。数量候选补充品种最小数量与最小名义金额，避免理想数量低于下限时漏掉合法解。方向、时间、手续费、行情和资金开关不通过百分比扰动伪造；生成仍仅预览。

## MT01：杠杆硬边界修复（2026-09-29）

数值目标容差不能放宽品种规则。手动实际杠杆保留 0.01 精度，但必须在 1 至有效上限之间；未配置上限默认 100，配置上限不能超过系统 100，分类禁用杠杆时有效上限为 1。目标本身可稍超边界，但只有目标 ±5% 与合法区间相交才能生成；在交集中重新求解数量、保证金、仓位，不截断已经计算好的杠杆。

生成搜索、独立 preview、create 最终计算均检查范围；create 在持有品种共享锁后读取数据库最新上限及分类，即使品种 row_version 未更新也不能绕过最新上限。普通纯算术函数仍可用于数学验证，它不代表服务端允许创建该杠杆订单。原先需要 600 倍或近 1 亿倍的搜索场景现在应拒绝；不能将“数学可行”误报为“品种规则合法”。

## MT02：生成后浏览器确认的数值摘要稳定性（2026-09-29）

预览与创建摘要对 input、leverage、targetNet 使用原始 BigDecimal 去尾零后的标准表示，等价的尾零、科学计数法和零值不会被误判为参数变化；不经过 double，不作金额舍入。真正数值变化、用户、操作者、方向、时间、规格、资金开关等仍绑定摘要。规范化不展开巨大科学计数指数。

旧版已落库的幂等记录若原摘要不匹配，则从其审计 evidence.request 精确读取原请求，并使用记录中的 operator_id 按同一规范化规则重新比较；仍不匹配或证据无效即拒绝。兼容重试不会再次写订单或入账；未提交的创建仍执行权限、时效、杠杆与资金规则，已提交的幂等重放保留原有不受预览过期限制的语义。
