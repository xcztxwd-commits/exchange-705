# 持久化控盘说明

## 调用链与职责

管理端 `AdminAiControlController` 调用 `ForexQuoteMarketService`，后者保留行情接入及既有随机行情分流，将普通目标控盘交给 `PersistentPriceControl`。轨迹继续使用 `PriceControlPath` 的确定性算法；`ControlHistoryStore` 负责事务、任务、价格样本、原始行情和混合分钟存储；`ControlledKlineMerger` 统一处理最新 K 线、历史分页和批量查询。PC 和移动端图表读取后端合并结果。

有效源行情下从当前展示价开始；断源时依次选择最近确认完成的蜡烛收盘价、最后有效报价，无有效依据则拒绝。尚未完成时缓存的源蜡烛不会仅因时间流逝而被视为确认收盘。任务保存起点依据与原始时间，以服务器当前时间启动。

任务参数固定，持续保存秒级样本；包含起点和精确目标终点，10 秒任务为 11 个样本，合入实际涉及的分钟，不生成 10 根分钟蜡烛。停止只保存已经发生的轨迹；完成时间为计划结束时间。重启按保存参数幂等补齐，24 小时任务的批量恢复也有覆盖。

新建目标任务到期后进入“保持偏移”，不会自动接回源价。差额由目标价减去终点之前最后实际收到的源报价确定；没有后续源报价时使用启动时保存的参考报价，只有历史蜡烛时使用记录的起点依据。源有效时后续展示价为源价加固定差额，断源时静态保留最后控盘价，不补横盘。提前停止任务也保持停止时的价格和偏移，重复停止不释放偏移；明确恢复、切换来源或下一段控盘才结束原保持规则，仅影响后续行情。平滑恢复是独立任务，目标在启动时固定，恢复段结束后接回源行情。升级前已结束的旧任务不重新启用偏移。

管理端任务历史新增“替代历史行情”：目标轨迹结束或任务提前停止后可点击。按钮将该任务原时间段登记为已替代，合并结果标记 `historyReplaced`，刷新、分页、切换周期和重启后保留。重复点击幂等，不将轨迹移动到其他日期，也不删除原始行情。控盘段本来就自动持久保存；显式替代复用同一权威分钟数据，不复制整根分钟覆盖同分钟内其他任务和之后实际收到的行情。

## 数据库

迁移文件：`exchange-backend/src/main/resources/db/migration/create_control_history.sql`。应用启动执行可重复的增量建表，不删除旧数据。原七张表加本次两张表，共九张：

| 表 | 用途 |
|---|---|
| market_control_task | 参数、算法版本、起点依据、生命周期、请求幂等键 |
| market_control_sample | 按任务及生成时间唯一的价格样本 |
| market_mixed_minute | 权威混合分钟 OHLC、最后事件时间 |
| market_source_candle | 独立原始周期蜡烛与接收时间 |
| market_source_quote | 最后有效源报价及其原始时间 |
| market_source_tick | 实际收到的源报价 |
| market_control_resume | 已接回源行情的展示事件 |
| market_control_hold | 保持偏移的参考价、差额、启用/释放时间及最后生成价 |
| market_control_publication | 显式替代历史的任务、原时间范围及操作时间 |

时间统一为 epoch 毫秒，价格使用 DECIMAL。交易品种行锁串行化并发写入；任务进度、样本及蜡烛在同一事务中提交。保持偏移阶段按实际新源报价保存生成价格，原报价时间不刷新；相同源时间不重复采样。Redis 不承担控盘历史的永久存储。控盘配置在事务提交后才发布到内存注册表。

启动时冻结当分钟已有源快照，之后只合并实际收到的报价及生成价格；随后下载的整根源 OHLC 不得覆盖它。未受影响历史保留原始蜡烛；受影响大周期由一致的分钟数据聚合。同时间只有一根蜡烛，普通控盘无七天历史截断。

## 交易边界

`freshPrice()` 与前端共用成交报价：控盘运行中、手动偏移及保持偏移阶段均按后台当前展示价开仓、平仓；外部源报价过期不阻止这些阶段交易。只有源行情不可用且没有控盘或保持偏移时，才因行情问题拒绝交易。不增加停市日历。`executionExpiresAt` 单独表示服务器对当前成交价的有效确认，前端断连后仍会过期；续期不改写源报价或样本时间，也不生成历史蜡烛。随机行情环境限制、结算汇率校验、余额和订单校验不变。

## 数据完整性边界

- 上游 OHLC 无法还原未观察到的秒级路径；缺失分钟/部分快照明确标为不完整，不伪造历史。
- 非 UTC 市场缺少可靠周期锚点，或日/周跨度涉及未知交易时段、休市及夏令时边界时，无法可靠合并的周期返回缺失提示，不猜测平移。
- 升级前未保存的历史无法凭空恢复；可识别的既有运行任务按保存参数导入。
- 历史持久保存会增加数据库占用；本次不增加自动清理策略。

## 局域网启动与独立强度修复

局域网 HTTP 不提供 `crypto.randomUUID()`，原提交代码在请求发出前抛错。现使用同样基于 Web Crypto 安全随机数的 UUID 生成，并将生成步骤纳入错误处理。已在 `http://10.185.9.191:17051` 的真实非安全上下文确认该旧 API 不存在，修复后的按钮仍能提交到独立真实后端。

波动强度不再依赖随机开关，空值会被明确校验。新任务使用算法版本 2：普通控盘叠加四秒规则波形，随机控盘使用带种子的随机波形；两者幅度均随强度 1–10 增大，并在端点收敛。强度可使中途价格超过目标，目标只约束计划终点。既有版本 1 任务及未带版本的随机行情事件继续用旧算法，避免重算历史。无需新增数据库列。

验证包括：真实局域网按钮关闭随机震荡、设置强度 8 并成功启动；源异常、运行中重启、精确终点、保持偏移、历史替代和恢复均通过。新增两种波形幅度与端点测试、版本 2 持久化重启测试、无版本旧随机事件兼容测试。后端 90/90、前端 25/25，均无失败；管理端 localhost 与局域网浏览器回归、生产构建和部署通过。证据为 `%TEMP%\705-intensity-isolation.log`、`705-intensity-lan.log`、`705-intensity-live.log`；截图 `%TEMP%\705-intensity-live\admin-lan-start.png`。

## 控盘报价变化但图表收盘价被覆盖

真实 USDJPY 数据中，上游 OHLC 页尾的非周期边界报价快照也被缓存为源蜡烛。合并一个受控分钟时，这些快照以多个不同秒级时间点进入分钟聚合，排在权威混合分钟之后，最终覆盖其收盘价；接口可观察到单个一分钟蜡烛的 `minuteCount` 为 4–5。

修复在源蜡烛读取、合并及历史起点选择中排除非周期边界快照；分钟内实际收到的报价仍由原有独立报价链路记录。源数据库原记录独立保留，不删除、不重算已保存的控盘样本。实际 USDJPY 受控分钟已核验 `minuteCount=1`，收盘价与混合分钟存储一致。

新增回归测试在旧实现上先失败（应一根，实际三根），修复后验证分钟和五分钟收盘价不会被源报价尾条覆盖。隔离真实后端主动注入同类污染数据，PC 四次图表采样为 91.97/92.27/93.71/93.98，移动端为 95.83/95.74/97.94/98.73，刷新后保持正确，页面无脚本错误。既有两端跨分钟、周期切换、历史翻页和随机历史浏览器回归通过。证据：`%TEMP%\705-candle-fix-before.log`、`705-candle-isolation.log`、`705-chart-fix-live.log`；截图位于 `%TEMP%\705-chart-fix-live`。
