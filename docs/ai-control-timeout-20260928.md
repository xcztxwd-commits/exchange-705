# 2026-09-28 管理端控盘页超时处理

## 已确认与未确认

- 截图的 `timeout of 10000ms exceeded` 来自管理端 Axios 的 10 秒请求期限。
- 原页面将状态读取与历史读取串行放在同一 `try/catch` 中。历史读取变慢会阻塞后续状态轮询；历史失败也会设置 `statusError`，导致状态正常时全部操作仍被禁用。这一故障放大路径已通过隔离浏览器延迟注入验证。
- 首次状态请求失败后，后续轮询不会重新初始化表单，可能留下默认时长、强度和目标价格；本次一并修复。
- 线上排查时 USD/JPY 状态及历史连续 80 次读取均成功，范围 258–1,341 ms，平均 386.4 ms。线程快照未捕获死锁，数据库快照未发现活动锁等待。因此无法断言原始超时是网络、数据库还是其他后端请求阻塞，也不能仅凭截图判断超时发生在状态还是历史接口。
- 后端日志另有采样主键重复异常，以及一次客户端断开后的 `Broken pipe`。未获得它们与截图请求的关联证据；本次未更改采样、结算、事务或交易逻辑。

## 修复

- 状态与历史请求分开调度、分开报错；状态继续每轮完成后约一秒刷新，历史完成后至少五秒再读取。
- 慢历史请求不再阻塞状态；历史失败保留已显示记录并自动重试，不误禁用正常状态下的操作。
- 真正的状态失败仍禁用操作，避免用过期状态提交；请求时限仍为 10 秒，未通过延长期限掩盖问题。
- 保留首次加载的表单初始化意图，重试成功后正确填充服务器配置；普通轮询不覆盖用户草稿。
- 管理端生产构建 API 地址固定为同源 `/api`，与原 Docker 构建设置一致。
