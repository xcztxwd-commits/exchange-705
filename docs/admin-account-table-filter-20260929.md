# 原后台真实 / 模拟账户表格筛选

## 本次范围

按修正后的需求修改现有后台，不再使用独立“账户数据查看”入口。用户端模拟账户创建、免实名与账户切换属于此前的独立实现，本次不重复改动。

所有接入表格使用两个复选框：真实账户、模拟账户。主页面首次进入仅勾选真实账户；两个同时勾选合并展示；都不勾选返回空表。用户 ID、关键字、状态、日期等原查询条件继续生效。变更账户筛选清空旧行、回到第一页；跨环境查询失败不回退到真实数据。每条记录增加账户类型，表格行键包含账户环境，避免两套数据库相同 ID 冲突。

## 接入清单

- 用户列表；用户收款银行卡、数字地址；下级用户；资金明细及交易、充值、提现、贷款、理财分类表。
- 合约、期权订单表。
- 充值审核、充值详情、提现审核。
- 贷款审核、贷款资料审核、实名审核。
- 理财订单、收益明细。
- 代理列表、代理下级列表、代理业绩下级表。
- 站内信表。
- 活动列表、投递回执、体验金流水。
- 统计页面同步接入账户类型筛选。

用户详情打开时跟随点击记录的账户环境；钱包、下级、资金明细、收益、回执、流水的嵌套表具有独立筛选。嵌套表首次打开跟随上级记录，不会点击模拟行却显示真实详情。普通公告、币种配置、管理员、角色、后台操作审计等非客户账户数据表不纳入环境筛选。

## 实现与安全

前端复用 `AccountTypeFilter`、`useAccountTable`、`accountTableRequest`，不另建一套表格。真实数据仍走原接口；模拟查询经真实后台 `/api/admin/account-query` 转发。该入口校验管理员角色及每个原模块、详情、导出权限；代理账号不能借此查询全局模拟数据。

模拟进程 `/api/simulation/admin-query` 校验共享密钥和固定只读路由，然后内部转发至已有查询 Controller，复用原查询语义。拒绝任意路径、写操作和缺少密钥的请求。只有已验证内部转发才临时进入只读查询上下文，外部 header 不能伪造该上下文；请求结束恢复原安全上下文。真实进程验证远端 `X-Account-Environment: DEMO`，错误不会读取真实数据兜底。

模拟或混合视图为只读，前端禁用写入并在请求封装再次阻断；切换视图不会把原模拟记录详情变成真实写入目标。模拟上传凭证使用 `/demo-uploads/`，不拼接真实上传目录。

充值汇总使用十进制字符串加法；CSV 导出合并当前选中环境并增加账户类型列，保留带引号、换行的字段。CSV 远端内容类型和字节内容保持原样。

## 部署与边界

1. 同步部署真实后端、模拟后端与后台前端。
2. 沿用 `compose.demo.yaml` 的 `SIMULATION_INSPECTION_KEY`（至少 32 字符随机值）及 `SIMULATION_INSPECTION_URL`。密钥仅服务端持有，不能放入前端；模拟库、缓存、上传目录保持独立。
3. 确认 API 网关的 `/demo-uploads/` 路由可达；在实际双环境验证钱包、订单、汇总和导出。
4. 为防止普通管理员读取其他管理员发送的站内信，模拟站内信跨环境查看仅向超级管理员开放。其余查询沿用映射的原模块权限；代理账号不开放跨环境全局查询。
5. 混合分页通过两侧原分页查询前缀合并，最多浏览前 10000 条；更深页提示缩小条件。连续翻页不是跨库事务快照，期间新增数据可能引起位置移动。
6. 此次不开放后台对模拟记录的审核、充值、修改或删除；需求为筛选查看，不扩大写权限。
