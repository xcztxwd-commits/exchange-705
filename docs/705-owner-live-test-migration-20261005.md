# 705 当前所有者授权的线上测试环境迁移

## 授权变更与边界

2026-10-05，项目所有者在当前会话明确要求：“跳过批准环节，目前线上环节无真实用户，允许直接迁移”。这是所有者关于当前环境的陈述及执行指令，不是从数据库余额推断的环境性质，也不是两名独立人员的签名。

新增显式 `--owner-live-test-authorization` 路径，供当前授权的线上测试环境使用。默认独立签署的正式生产路径保持不变。此路径不设置源码注册表中的 `release_approved`，不伪造运行时验收，不使用 fixture-policy 或 local-owner 模式操作线上库，不制造签署人或批准密钥。迁移终态的 activation 仍为关闭；新版必要验收与业务开放仍须实际完成。

授权收据保留在受限 `rollback/multitenant-20260929` 中，不提交 GitHub。它必须包含原始人类指令收据及其 SHA-256、授权到期时间、当前源码指纹、逐份迁移 SHA-256、精确源与独立恢复目标身份、排空的写入者清单、恢复责任，以及 plan/backup/restore/source/target 的完整绑定。执行日志为明确标注的未签署 SHA-256 证据链，不声称具备独立批准的真实性保障。

实际 MySQL `read_only=1`、连接排空、不同恢复实例/UUID/datadir、备份恢复逐字段一致、原有资金/订单/聊天事实保存、阶段 INTENT/COMPLETE/FAILED_UNCERTAIN 记录、未知 DDL 不重放及包/schema 版本保护继续执行。任何一项失败都应停止；跳过批准不等于跳过这些检查。

## 本次发现及修复

1. 线上两库已经具有 V2026092903/V2026092904 的四个活动列。直接再次执行这两份 `ADD COLUMN` 会重复建列。受控 plan 现在仅登记既有精确审定的列类型、可空性和默认值；apply 重查同一契约并记录 `REUSED_EXACT_REVIEWED_LEGACY_COLUMNS_NO_DDL`。缺列、部分存在或结构不符不得推定已迁移；其他阶段不复用。
2. 历史准备快照压缩后约 474 MB，原有 restore 路径把整个解压 SQL 读成字符串再编码。改为从文件流导入隔离恢复实例；SQL_MODE 修复也仅流式处理已识别的三行触发器头。原始 dump 不改写，未知/重复/缺失触发器头拒绝。不得以节约内存为由减少全字段校验。
3. 用户表原有主键是 `user_account.id`。钱包等业务表的 `user_id` 引用它；本次并未新增另一套用户编号。只读盘点的 53 条历史记录引用了 24 个缺失的用户主键：资产账户 6、收益历史 2、划转历史 34、数字地址 1、用户菜单 10。六个孤立资产账户余额为零不证明其余历史可以删除。缺失身份不得补造；只能对原字段和金额进行受限、可恢复、逐行对账的封存演练与处理。
