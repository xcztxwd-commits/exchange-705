# 已知失败的最小修复与隔离登记

本轮承接四项 K 线、月线退役、移动实时配对、零比例数量修复。原始失败证据保持不变；本轮记录位于 `C:/workspace/fx/new/kline-sync-known-fixes-20261010/`。

## 业务变更

- 管理端内部只读转发先识别服务器私有证明，再走正常入口；普通请求继续执行原 Host、转发头、Origin、登录及租户校验。证明限定原 `/api/admin/` 范围，退出仍清理租户上下文。
- 失权命令缓存键补服务器租户前缀。原命令主键为 `(tenant_id,id)`；一个租户的失权不会再使另一租户同 id 命令跳过。失权写者仍禁止重领租约，数据库条件、锁序与准备逻辑保持原样。
- 历史恢复组件补读取、恢复、撤销权限声明及异步等待后重核；四张表复用现有 AdminTable 与列偏好。其余页面布局和生命周期沿用现状。

## 测试契约修复

夹具补路由、订单监视器、卸载回调与真实配置加载；加载失败后仅恢复策略不能保存。后端夹具补实体必填字段、重复 schema 初始化及手工构造服务的配置依赖。本地上传测试明确使用 local 存储，不改变生产 MinIO 模式。

HTTP/WS 测试使用已有客户端发送匹配的虚拟 Host；仍有 Host/转发头不匹配的拒绝断言。nginx 原 `$http_host` 保留端口，测试核验其与转发头一致，不降级代理配置。

S4 原旧 reader 和归档返回未修改。差分仅复制旧响应的 `data` 并补无恢复夹具的显式 `historyRestoreRevision=0`，其余字段仍完整严格对照，证据同时保存 raw legacy response。排序策略元数据读取只允许完整租户/品种主键、最多一行；其余分页仍必须 LIMIT、只读、禁 OFFSET。原相同 received time、不同价格的 legacy tick 仍明确拒绝，另用独立无歧义夹具保留完整差分覆盖，禁止猜测旧 close。

## 隔离登记边界

独立审查核对全部 42 个待登记 Java 文件的租户谓词、缓存键、回调、文件和入口边界，发现并修复失权命令缓存缺少租户的问题后复查。逐文件原/现 SHA256、规范化指纹、分类和理由保存在 `review-backend/registration-review-final.json`；仅按匹配的当前源码登记。30 个旧登记 SHA 无可匹配旧 blob，按当前边界审查，不以 HEAD 假装旧登记基线。

迁移清单仅补已经存在的两项 `0703` DDL、两个私有恢复表及真实业务关系，解析器按主/次版本数值排序。打包 epoch 保持实际资源值 `2026100703`。所有原 SQL 字节保持原样；未自动收录被后续迁移替代的旧 authoring inputs。现有 relations 的单字段格式不能表达 minute→job 的完整三列外键，真实 DDL 和外部证据保留该列组。

源码登记、构建成功和隔离库演练不构成生产发布或全部业务验收。`release_approved` 与原 release blockers 保持原样；未执行生产月线清理、发布或上线后五分钟验证。完整日志、退出码、逐例结果、补丁和 SHA256 清单以本轮证据目录为准；缺失专用认证/资源夹具的用例明确列为未验证。
