第二轮真实 MySQL 验收发现重复开户与客服容量越界；首轮 H2 通过不能覆盖这两个缺陷。本次已把配置/权限读取移到序列化行锁之后，并覆盖转接等同源入口。真实 MySQL 5.7.44 / REPEATABLE-READ 三个独立新库各 47/47，通过原独立复现夹具 3/3；H2 对照 50/50。未降低隔离级别、未删除约束、未吞错或自动重试掩盖。

详细根因、事务边界、负向对照、源码哈希与测试证据见 [MySQL RR 修复报告](C:/workspace/fx/705/docs/support-mysql-rr-fix-20260929.md)。这是指定并发缺陷的修复证明，不代替尚未完成的迁移、重启、真机和生产联调验收。


## 1. 需求与现有业务衔接

原系统有后台多账号、角色/按钮权限、客服外链、提示音上传与通知轮询；没有站内会话、排队、私有聊天图片和客服监督数据模型。前端分为后台、移动端和 PC 三个 Vue 应用，后端是 Spring Boot/JPA/MySQL。

本次沿用登录身份、客服入口图标、外链配置、角色权限、日志模块和浅色绿色主题。新增功能独立归入“客服与消息”，不让客服账号默认获得财务、用户管理等权限；角色原有权限也不会被自动增加。模拟账户和真实账户共用真实身份的客服/站内信，避免消息被写入模拟交易后端。

采用数据库持久化与短轮询，而不是另外搭建消息队列或 WebSocket 服务。聊天约 3 秒刷新，队列和通知约 5 秒刷新，配置约 10 秒刷新。多实例并发依靠数据库行锁和唯一约束，不依赖进程内状态。

## 2. 已实现

### 用户端
- 登录用户进入客服后发起会话；每个用户只能有一个未结束会话。
- 按进入先后显示排队位置，客服离线时允许先留言。
- 文字、图片、历史会话、发送失败重试、已读回执、结束并重新发起会话。
- 移动端与 PC 共用聊天实现，各自保留身份请求和语言适配。
- 独立站内信列表、详情、未读提示、单条与全部已读、分页。
- 保留原客服入口，可切换外部平台、站内客服、关闭。关闭不删除已有会话；站内信开关独立。

### 后台
- 独立客服工作台；多个管理员账号可同时上线接待。
- 我的会话、等待队列、接待容量、抢单冲突保护、暂停接待、转接、结束。
- 65 秒无心跳视为不在线；已分配会话不会静默转给他人，保留责任归属。
- 超级管理员监督全部聊天、导出含图片的 JSON 证据包。监督阅读不消耗客服未读数，不允许冒充其他客服回复。
- 站内信按用户 ID 定向发送，单次最多 200 人；发送前确认、服务端幂等、已读状态；普通发送者只看自己的发送记录，超管可看全部。
- 默认欢迎语、离线提示、按顺序匹配的 IPv4/IPv6/CIDR 欢迎语规则。

### 提示音
- 检查到现有后台有提示音设置/上传入口，但源码未附可直接复用的本地音频素材。
- 已生成并接入两段原创合成 WAV：arrival.wav（清脆三音，约 0.75 秒）与 reply.wav（柔和双音，约 0.50 秒）。不使用第三方下载音源。
- 默认分别对应后台新客户/新消息和用户新回复；设置页可试听、更换或关闭，也支持原上传模块返回的 /api/uploads/audio/ 地址。
- 每个浏览器需主动点击“开启提示音”，避免违反浏览器自动播放限制。新消息水位与未读数分离，先读后通知的竞争不会丢掉到达提示。

## 3. 权限配置

在现有角色/权限管理模块配置以下菜单与按钮；接口服务层也校验权限和会话归属，隐藏按钮不是安全边界。

- `support`：客服工作台菜单。
- `support:detail`：查看自己当前负责的聊天。
- `support:claim`：上线、查看等待队列、接待。
- `support:reply`：发送文字。
- `support:image`：收发私有图片；发图同时需要回复权限。
- `support:close`：结束会话。
- `support:transfer`：转接给在线且有容量的客服。
- `support:audit`、`support:export`：仅超级管理员有效，普通角色即使错误分配也不能越权。
- `inbox`、`inbox:send`：查看自己发出的站内信、发送站内信。
- `support_settings`、`support_settings:save`：查看、修改渠道与消息设置。

建议新增“客服”角色，只授予 support 菜单及 detail/claim/reply/image/close/transfer。需要发送站内信时另授予 inbox/send。设置权限留给运营负责人。沿用管理员列表创建不同账号，不共用密码。业务代理商 ROLE_AGENT 不是客服账号，不能进入客服后台。

## 4. 数据、安全与证据边界

新增五张表：support_conversation、support_message、support_attachment、support_presence、inbox_letter。复用 system_config 中的 `support.settings` 原子 JSON；外部客服地址继续使用原 `customer.service.link`。

- 消息正文只追加，没有编辑、撤回、删除接口；图片私有存储在数据库，必须校验会话归属后下载，不放公共 uploads。
- 图片输入最多 5MB、1600 万像素，解码后重编码 PNG，去除元数据和原始可执行混合载荷；输出最多 10MB。
- 重试 requestId 校验内容一致，避免重复发送；创建会话每用户最多 10 次/小时，发送每会话每侧最多 30 条/分钟。
- 记录发送身份快照、服务器时间、原始 IP、接待/转接/结束事件、图片哈希、前一消息哈希及 SHA-256 链。
- 消息时间固定秒精度，避免不同数据库 datetime 精度破坏导出哈希；同秒顺序由递增消息 ID 确定。
- 导出包含导出者、导出时间、原始消息、Base64 PNG 与 chainValid 校验结果；上限 2000 条消息/32MB 图片，超限使用受控数据库备份归档。
- 普通操作日志不写聊天或站内信正文，避免通过日志模块绕过聊天隔离。证据导出纳入操作日志。
- 哈希链不是可信时间戳、不可变存储或司法认证；拥有数据库最高权限的人仍可能重写整条链。生产应另配访问控制、加密备份、异地不可变归档和保留策略。这里不承诺证据必然具有某种法律效力。

## 5. 上线操作

1. 备份生产数据库和当前发布包；确认本次改动与工作区其他在途改动已经合并审查。不要直接整目录覆盖生产。
2. 构建并发布后端、后台、移动端、PC。项目现有 JPA ddl-auto:update 会创建新增表；生产如采用受控迁移流程，应先在预发布库审核生成的 DDL、唯一索引、字符集和存储空间。
3. 后端启动新增“客服与消息”权限目录，不自动给旧角色授权。现有权限初始化所需 admin-permissions.json 在原工作区缺失，已根据现有权限草稿补齐；部署时确认与最新权限目录一起发布。
4. 超管在角色管理授予客服角色权限，管理员列表创建多个客服账号。
5. 打开“客服与消息设置”，选择“站内客服”、按需开启站内信、配置容量与欢迎语；两种默认提示音已可直接使用。
6. 客服打开工作台，点击“开始接待”和“开启提示音”；用户首次进入同样点击“开启提示音”。用两个账号完成一次真实排队、发图、回复、转接、站内信收阅和超管导出。
7. 反向代理必须覆盖 X-Real-IP，不转发客户端原值。客服优先读 SUPPORT_TRUSTED_PROXIES，否则复用 SECURITY_TRUSTED_PROXIES；均未配置则仅信任直连地址。现有 compose 已配置 SECURITY_TRUSTED_PROXIES，现有 nginx 覆盖 X-Real-IP。仅填真实代理网段，不配置 0.0.0.0/0。
8. 默认保持“外部客服 + 站内信关闭”，不擅自改变原线上业务。需要上线时按上述设置启用。

## 7. 明确范围与后续验收

- 当前是已登录用户客服；没有新增匿名访客身份/登录系统。
- 移动网页保持运行并获得播放许可时可响铃；关闭页面、锁屏、浏览器暂停后台时不保证声音。本次未实现 Web Push/原生系统推送，需真机 Safari/Android 补验。
- 站内信是后台定向发送，不是用户之间私聊，也不是百万用户广播。
- IP 规则按 IP/CIDR 匹配，不是国家地理识别。
- 后端 HTTP 测试是真过滤链/服务/数据库；浏览器测试使用 mock，两者不应称作已完成生产端到端联调。
- 本轮已补真实 MySQL 5.7 定向并发回归；生产级压力测试、生产代理联调、迁移/重启、真机后台声音及长期归档恢复演练仍未完成。
- 会话权限按当前负责客服判断：转接后原客服不能继续读取，超管可监督完整链路。
