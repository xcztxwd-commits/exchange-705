# 多租户平台设计方案

日期：2026-09-29。状态：需求确认后的设计稿，尚未实施。本文不代表功能已上线、数据库已迁移或隔离测试已通过。

## 1. 结论与已确认需求

采用一套业务代码、共享 MySQL 数据库、业务表 `tenant_id` 字段隔离、共用租户后台入口、独立总控后台。复用现有 Spring Boot/JPA、Vue、Redis、Nginx，不为了约 10 个租户、每租户约 200 用户和 10 人同时在线引入微服务、分库或额外消息队列。

这只是按需求规模选择的架构，不是容量测试结论。共享实例仍有故障、资源争抢和应用缺陷影响多个租户的风险；不能声称与独立数据库具有相同隔离强度。

### 1.1 产品边界

- 首期 5 个租户，一年约 10 个。
- 每租户只有一个当前有效的前台域名，由总控分配，暂不支持租户自带域名或多个域名。
- 更换域名不修改租户 ID，不迁移账号或业务数据归属。
- 当前项目及全部历史业务数据归入默认租户。允许停机迁移。
- 不同租户允许使用相同用户邮箱或手机号；密码、实名、余额和业务记录相互独立。
- 租户后台保持现有使用方式。后台登录名全局唯一，只输入账号和密码，不输入租户编号。
- 租户负责人可创建本租户管理员、客服、代理并分配授权范围内的权限。总控也可添加账号并查看管理员信息。
- 租户的品牌、用户、代理、角色、币种、交易参数、产品、充提、客服、站内信、短信和邮件配置独立。原始公共行情源可以共享。
- 总控业务数据查看页只读；租户创建、域名、授权、账号开通等总控管理操作本身可写。
- 总控一键进入指定租户后台后直接拥有该租户超级管理员级业务操作权限，不再要求另切只读/维护模式。
- 总控访问使用真实总控身份，不冒用租户管理员，不创建隐藏租户账号，不挤掉租户人员的会话。
- 总控进入时自己的页面显示“总控管理”。不在租户管理员列表显示，不向租户发送进入通知；保留独立总控审计记录，不伪造业务流水，不保证修改结果不可被察觉。
- 在线人数按最近 5 分钟有效活动的真实用户计数，支持明细及最近查看页面，不重复计入模拟账号。
- 聊天记录保留策略默认一年；实现自动清理能力，但初始 `auto_delete_enabled=false`，测试期间不会因超过一年而自动删除。

### 1.2 本方案选定的技术默认值

以下是可调整的实现默认值，不是新增的用户强制要求：一键进入交换票据有效期 60 秒、仅能使用一次；访问会话绝对上限 60 分钟、闲置 15 分钟到期；在线列表沿用 5 秒刷新；在线活动时间最多每用户每 30 秒持久化一次。生产启用总控 MFA；高风险操作保留确认与重新验证，不改变一键进入后具有写权限的事实。

实际域名、总控初始账号和模板配置清单属于实施前配置项，不阻塞设计定稿。尚无明确运营地区，因此本文不作法律合规结论；上线前仍需确定隐私告知及留存要求。

## 2. 当前项目核查结果

本轮只读取源码和已有文档，没有连接运行数据库、修改生产配置或执行业务写入。

- 后端为 Java 8、Spring Boot 2.7.18、JPA/Hibernate；仓库 compose 配置使用 MySQL 5.7 和 Redis。运行环境版本需部署前另行确认。
- `UserAccount` 的邮箱、手机号目前全局唯一；`AuthService` 按邮箱登录、按全局邀请码关联上级，没有租户上下文。
- `SystemConfigService` 使用 `findByConfigKey` 与 `findAll`，配置当前为全平台一套。
- `TradingSymbol.symbol` 当前全局唯一；改为租户独立币种时必须连同唯一约束和按 symbol 查询一起改造。
- `AdminPermissionService`、`BackendAccess` 当前有 `super_admin` 放行逻辑，不能直接沿用为跨租户授权。
- `AdminAuthService` 先按管理员账号/邮箱查找，再按用户邮箱查找代理。允许用户邮箱跨租户重复后，这个后台登录回退链会产生身份歧义，必须改造。
- 站内客服已包含私有附件、监督、证据导出与哈希链，但排队、会话、客服在线查询没有租户维度。
- 当前在线人数从用户列表遍历计算；后台每 5 秒刷新。应改为租户范围内的数据库统计与分页，不读取所有租户用户到内存。
- 当前后台认证状态使用全局 `localStorage.admin_token`。总控同时打开多个租户时不能继续共用这个键。
- `DomainUtils` 使用 Origin/Referer 辅助记录登录来源，不能直接作为租户权限来源。
- 项目还有真实/模拟账户、独立模拟后端、缓存、推送、资金快照等路径，租户改造不能只覆盖常规 HTTP CRUD。
- 工作区已有大量在途改动；后续实施必须先固定工作基线并逐项合并，不能整目录覆盖或重置。

## 3. 入口、域名与登录

### 3.1 三类入口

示例域名不代表已配置：

- `control.example.com`：总控后台，新增独立前端构建入口/应用。
- `admin.example.com`：所有租户共用现有后台，账号密码登录。
- `a.example.com`、`b.example.com`：不同租户前台，一个租户一个域名；PC 与移动端使用同一主机下的入口或路径，不因此增加第二个绑定域名。

后端保持同一个应用，划分 `/api/control/**`、`/api/admin/**` 与用户 API 的身份及授权边界。独立前端、域名和接口前缀不是替代鉴权的安全措施。

### 3.2 域名信任规则

- 仅在总控配置的基础域下分配明确层级的子域，规范化大小写与端口，精确匹配，不用字符串包含判断。TLS 证书必须实际覆盖该主机名。
- 域名绑定有唯一约束，只有完成路由和证书检查后才激活。泛域名 DNS/TLS 不意味着未知主机可以访问任意租户。
- 网关覆盖转发头，只信任实际配置的代理；后端不直接暴露公网，防止绕过网关伪造租户来源。
- Origin/Referer 可用于来源检查，不能替代绑定表及账号归属验证。浏览器传来的租户 ID 只是选择值，不是授权证明。
- 未知域名或缺失租户上下文直接拒绝，绝不自动归入默认租户。健康检查单独使用不返回业务数据的受限端点。
- 用户令牌必须与域名解析出的租户一致；A 用户令牌在 B 域名的请求失败。
- 默认域名变更采用新域名准备、原子切换、缓存失效、旧域名停用流程；不通过长期保留旧域名别名变成多域名绑定。
- 切换后旧页面写请求失败。用户可在新域名重新登录，数据和账户归属不变。旧域名有解绑留痕和人工复用检查，防止立即分配给别人导致旧书签误入。
- Cookie 不设置共享父域，CORS 使用受控精确来源；总控和普通后台不共享总控凭据。

### 3.3 全局唯一后台登录名

新增最小的后台登录标识注册表 `backend_login`，统一注册管理员及需要登录后台的代理的账号名称。字段包括规范化账号、租户 ID、主体类型、主体 ID、启用状态；规范化账号有数据库全局唯一约束，同一主体只绑定一个当前账号。

这个表是后台登录名的权威查找入口，不是新的代理业务模型；管理员密码继续使用管理员的密码哈希，代理可继续使用其已绑定用户身份的密码校验。租户 ID 和主体关系由服务端验证，不允许租户自填其他租户主体。

- 管理员、客服、代理如果共用后台登录框，就必须共用唯一名称空间，否则不同租户重复用户邮箱仍会使代理登录歧义。
- 普通用户邮箱继续只在租户内唯一。代理的“后台登录名”与前台邮箱分开；不改变代理仍属于本租户用户体系的事实。
- 后台不再无条件回退为任意用户邮箱登录，也不允许“某个账号名恰好等于别人的登录邮箱”形成查找优先级歧义。
- 默认不提供管理员邮箱登录别名，仅账号密码符合已确认需求。旧账号/邮箱登录使用情况在迁移清单内检查，不静默丢弃必要入口。
- 创建及改名冲突仅提示“账号不可用”，不返回它属于哪个租户。
- 总控从独立总控身份表登录，不是默认租户的超级管理员。两个身份不能相互冒充。
- 密码哈希、当前令牌和第三方密钥不包含在“查看所有信息”的普通返回中；密码只支持安全重置，不提供明文查看。

## 4. 权限与总控访问会话

### 4.1 身份分类

- 总控管理员：管理租户、策略、总控账号和只读监管入口，可创建绑定目标租户的业务访问会话。
- 租户负责人：租户内最高可授权权限，不能操作其他租户或改变总控锁定策略。
- 租户员工：角色菜单、按钮及数据范围内操作。
- 租户代理：本租户内既有代理数据范围，不能因多租户改造自动扩大为整个租户。
- 总控访问会话：操作者仍是总控；拥有目标租户超级管理员级业务权限，但不能通过该业务会话切换租户或调用总控策略接口。

租户普通业务请求的最终权限是：租户有效状态、功能授权及开关、账号权限、对象归属与业务状态共同约束。总控访问会话可获得租户内最高业务权限，但不绕过资金并发控制、账务一致性、不可变记录和租户边界。总控可在自己的控制面显式修改租户授权和锁定策略，不能通过伪造租户参数解锁。

总控只读业务查看页只提供用户、订单、资产、实名、充提、代理、管理员、统计、在线用户及客服监督等读取接口。查看/导出审计记录的写入不属于修改租户业务数据；不复用会产生业务副作用的查询实现。

### 4.2 一键进入流程

1. 总控在租户列表点击“进入后台”。已有有效总控登录时直接进入，不先进入只读模式。
2. 后端检查总控身份、会话状态和目标租户，创建一次性交换票据，绑定目标租户、操作者、用途、过期时间和浏览器交换校验值。票据只存哈希。
3. 新标签页打开固定白名单后台地址。通过受控跨窗口消息传递一次性票据，并校验精确 origin、窗口来源和握手值；不把长期令牌放在 URL 查询串、日志或 Referer 中。
4. 后台专用交换接口原子消费票据并验证浏览器绑定，签发/建立绑定 `control_actor_id + tenant_id + access_session_id` 的短时会话。普通租户令牌不能调用此流程。
5. 页面显示“总控管理 / 当前租户名称”，直接具有该租户超级管理员的业务操作能力。每个标签页独立保存访问凭据，不写入普通管理员的全局 localStorage 键。
6. 请求时重新检查访问会话是否撤销、操作者是否有效、租户范围是否匹配；JWT 验签成功不能替代实时撤销检查。
7. 退出、超过时限、总控账号停用或强制注销后撤销。自动重试不得在总控访问凭据失效时退回普通后台令牌。

交换实现须专门测试跨窗口消息来源、票据重放和误绑定。sessionStorage 可用于按标签页保存凭据，但仍有 XSS 风险，且带 opener 新窗口可能复制初始存储；必须清理旧上下文并明确建立新会话，不把“存储隔离”当作服务端授权。禁止租户注入任意脚本或未经清洗的 HTML，以免共用后台源受到恶意内容影响。

### 4.3 可见性与审计

- 不创建租户管理员记录，不占租户管理员数量，不给租户发送总控进入通知，不显示为租户在线员工。
- 总控访问、检索敏感实名材料、聊天读取、导出和修改均记录真实总控身份。
- 总控专用访问日志仅总控可见；普通租户日志不泄露总控会话凭据或专用审计明细。
- 资金调整、充提审核等必须留下真实业务流水及状态历史；不能伪造为某个租户管理员操作，也不能为了隐藏总控而删除业务证据。
- 钱包余额调整通过有原因、有幂等键、有事务/锁及审计的账务入口，不提供任意 SQL 或无流水直接覆盖余额。
- 高风险修改保留确认、原因及必要的重新验证；这属于操作安全措施，不限制用户已确认的总控写权限。
- 总控账号不能读取密码原文、修改已固化审计记录或删除未到清理条件的聊天证据。监管业务权限不等于任意破坏数据完整性的数据库权限。

## 5. 数据模型和防串租户规则

### 5.1 新增最小控制面模型

- `tenant`：不可变 ID、编号、名称、唯一当前域名、状态、模板版本、策略版本和配置完整状态。
- `tenant_policy`：租户、策略键、授权值/锁定值、版本。存功能授权、配置锁定、客服强制渠道等；只有总控控制面可修改。
- `control_admin`：独立总控账号、密码哈希、MFA 状态、账号/会话版本。
- `control_access_session`：操作者、目标租户、票据哈希、消费标记、访问会话、签发/过期/最后活动时间、撤销状态。票据状态和会话转换需原子处理。
- `control_audit_log`：操作者、目标租户、访问会话、请求标识、动作、对象、结果、脱敏变化、原因、IP 和服务器时间。
- `backend_login`：全局唯一后台登录名称注册表。

配置和功能开关尽量复用现有 `system_config` 并增加租户维度，不另外设计通用规则引擎。模板使用版本化白名单配置，不复制原始生产数据库。

### 5.2 数据分类

**租户私有数据**：用户、管理员、角色及授权关系、代理关系、资产/流水/快照、订单和结算、充提/收款设置、实名/银行卡/地址、借贷、理财、活动奖励、公告、站内信、客服所有表、验证码、币种业务配置、操作日志和后台偏好。

**受控共享数据**：代码定义的权限目录、基础公共市场标识、原始行情及通用静态资源。租户可选择/配置自己的业务，但不能通过普通配置接口修改这些全局定义。

**总控数据**：租户注册、策略、总控身份、访问会话、总控审计。没有租户上下文时只能使用被明确授权的总控路径，不能因此任意查询私有业务表。

业务表默认 `tenant_id NOT NULL`，租户 ID 不使用域名或名称。旧记录 ID 尽量保留，主键可继续全局唯一；“ID 全局唯一”不能替代租户校验。

### 5.3 关键约束与索引

- 用户：`UNIQUE(tenant_id, normalized_email)`；手机号按现有标准化规则使用 `UNIQUE(tenant_id, normalized_phone)`，空值语义单独验证。
- 后台名称：`backend_login.normalized_account` 全局唯一；角色编码则 `UNIQUE(tenant_id, role_code)`。
- 系统配置：`UNIQUE(tenant_id, config_key)`；币种业务配置：`UNIQUE(tenant_id, symbol)`。
- 父表增加 `UNIQUE(tenant_id, id)`，子表以 `(tenant_id, user_id)` 等复合外键引用，覆盖订单用户、代理上级、管理员角色、客服会话与附件等关键关系。共享目录引用明确不带租户，但绑定记录必须属于租户。
- 修改 tenant_id 不在业务编辑 DTO 中开放；读写会话不可跨租户切换。后台改名与创建在事务内维护登录名称注册表。
- 常用列表索引按租户、状态、时间、ID 组合；在线统计按租户和最后活动时间，分页按稳定 ID 排序。
- 幂等键在租户和业务类型内生效；遇到既有外部支付全局交易唯一要求，继续保留全局防重复入账约束，不能机械地全部改成租户内唯一。

复合外键只防错误关联，不能阻止无 WHERE 的跨租户读取或更新。旧表列类型、引擎、孤儿数据和索引长度必须在实际 MySQL 版本上验证；不能依赖 CHECK 约束替代当前 MySQL 5.7 下的安全验证。

### 5.4 服务端强制访问边界

1. 身份入口先解析已验证租户；每个普通业务服务与数据访问入口必须取得非空租户上下文。
2. 查询、统计、详情、分页、导出、锁定记录、批量更新/删除必须在数据库查询条件中包含租户；不能先查全量再用 Java 或前端过滤。
3. 租户私有 Repository 不向业务代码暴露无租户参数的 `findAll/findById/deleteById` 等方法。显式租户查询作为主边界；框架过滤器只作补充。
4. 原生 SQL、JPQL 批量语句、EntityManager、启动初始化和后台任务登记审计清单，测试/构建检查阻止新增未登记的全局私有表访问；不能宣称一个拦截器会自动覆盖全部 SQL。
5. 更新和删除使用 `tenant_id + id + version/业务状态` 条件，并检查受影响行数。插入由服务端写入租户，不接受客户端覆盖。
6. 外部传入的用户、订单、角色、附件和代理 ID 必须在当前租户下验证。跨租户 ID 返回不泄露对象存在性的统一拒绝结果。
7. 批量请求发现任何越界对象，全批失败且没有部分资金或状态副作用。
8. 每个请求/任务结束时清理上下文；线程池、异步任务、错误路径和重试必须显式传播和恢复租户。一个 JPA 持久化上下文/事务内不切换租户，避免一级缓存带出其他租户实体。
9. 总控只读服务使用专用、受限、审计过的查询入口。需要汇总时显式声明租户范围，不提供可由前端打开的全局过滤绕过开关。
10. 资金/审核命令的审计与业务提交使用同一事务保存；失败尝试另记安全日志。关键修改不能在审计失败时仍成功提交。

## 6. 缓存、任务、文件、模拟账户和行情

- 所有私有缓存/锁/限流/幂等键包含租户；例如 `tenant:{id}:config:{key}`。私有行情覆盖和 WebSocket 订阅也带租户，公共原始行情另用 global 命名空间。
- 公开平台配置只返回白名单字段，不能把租户的 SMTP 密码、短信密钥、私有材料地址或内部策略完整公开。
- 第三方密钥在库内加密、页面掩码显示，支持替换不默认回显；模板不能复制这些密钥。
- 对租户设置的回调/外部客服等地址进行允许协议和用途校验；邮件、短信等可发起网络访问的配置需限制内网目标和资源消耗。
- 后台任务从受控任务入口枚举租户，为每个租户开启独立上下文/事务；暂停新增业务不暂停已有订单结算。任务重试和去重包括租户、对象、结算周期。
- 若任务发现缺失租户的业务记录，报警并隔离处理，不自动按默认租户结算。
- 文件路径包含租户只是组织方式；下载还必须验证归属和权限。实名、银行卡、聊天附件禁止公共直链。迁移历史上传文件需核对数据库归属及所有旧链接。
- 普通公开 Logo 可以缓存；带账号身份的数据不进入共享 CDN 缓存。前端租户切换要清空业务/权限缓存与 WebSocket 连接。
- 模拟账户和真实账户继续隔离，所有真实到模拟的身份校验、开户、目录同步都传播服务端验证的租户；不能仅传 user_id。客服、站内信、在线人数归真实身份，不重复计数。
- 公共行情采集只共享原始数据。交易对启停、手续费、交易参数和任何租户私有展示/模拟行情设置不能写进全局行情缓存。
- 每租户限制导出并发、客服附件体积、请求速率和异常资源使用，并设置总平台上限；软隔离不自动解决单租户耗尽资源。

## 7. 功能开关、锁定和租户状态

### 7.1 功能与配置不是同一套权限

功能目录至少覆盖现有期权、合约、理财、借贷、活动、模拟账户、充值、提现、站内客服、外部客服、站内信、代理及后台对应操作；最终清单由实际菜单和接口逐项登记，不以这里的举例作为遗漏功能的理由。

总控授权决定“允许经营”，租户开关决定“是否启用”，员工权限决定“谁能操作”。前端隐藏入口，后端同样拒绝新增业务请求，不能只改菜单。

配置策略支持：不允许、允许租户自行配置、强制固定值。例如客服可强制站内、禁止外链并锁定入口。策略变更增加版本并使缓存失效；旧页面仍不能写回总控已锁定的值。

关闭一个模块要保留历史查询、已有订单结算、到期处理、必要的平仓/赎回/退款和争议处理路径，不允许继续开新订单。不能把整组 URL 统一 403 导致资金无法退出。功能启停与紧急冻结资金属于不同命令，不混用。

### 7.2 生命周期

- 草稿：配置未齐，不开放用户注册交易。
- 正常：按授权和配置经营。
- 停止新增：禁止注册和新增风险业务，保留历史、已有订单处理及按规则执行的资金退出。
- 维护：前台维护提示，普通新操作停用；总控可进入排查，既有结算任务继续执行。
- 停用：禁止普通前台和租户后台登录，撤销已有普通会话；数据保留、监管入口保留、已有结算与资金退出转为受控处理，不直接丢弃。

第一期不提供“一键删除租户及全部数据”。实际提现冻结、用户封禁等沿用有审计的业务操作，不由停用标记暗中触发。

## 8. 在线用户与最近查看页面

在线口径为“最近 5 分钟有有效认证活动的真实用户”，不是精确 TCP/WebSocket 连接数，也不证明用户正在看屏幕。

- 普通用户有效业务请求更新活动时间；后台管理员/代理管理请求不冒充用户前台活动。后台列表轮询本身不能把被查看的用户标记在线。
- PC/移动前台在登录后的路由切换和页面重新成为可见时上报最近页面，不另用永久保活心跳改变用户已经确认的统计口径。
- 路由上报传白名单 page_code，例如 home/assets/option/financial/support，由服务端映射显示名；不采集搜索词、输入框内容、完整 URL 查询串、验证码或聊天内容。
- 保存 `last_page_code`、`last_page_seen_at`、设备类型及必要的去重序号，使用服务器时间；标注“客户端上报，最近访问”，不能把它当作不可伪造的浏览证据。
- 多标签页按最后一次有效的可见页面上报显示，无法可靠判断时显示“未知”，历史用户未上报不猜测页面。
- 用户列表接口同一个有效租户和代理数据范围计算总数、筛选及分页。一次响应内尽量共享统计时点，5 秒轮询自然存在延迟。
- 总控展示每租户在线人数，点击进入该租户明细；平台总数为各租户账号数之和，相同邮箱在不同租户不合并为一个人。
- 默认字段：用户 ID、账号、最近页面、页面时间、最近活动时间、端类型。IP/地区按查看权限显示；不复制完整浏览历史。
- 页面上报限流并约束长度；普通活动时间可节流到每用户 30 秒一次，明确最大刷新误差。

## 9. 客服监督、留存和清理

- 客服排队、接待容量、在线客服、会话抢单、转接、消息、附件、未读计数和站内信全部租户隔离。
- 租户负责人监督本租户客服，总控监督指定或授权范围内全部租户；监督阅读不消耗客服未读、不伪造客户已读、不冒充其他客服回复。
- 客服原文只追加，普通总控访问会话也不能原地篡改、静默删除。总控监督可导出文字和图片，导出范围及结果留审计。
- 默认保留窗口为一年，建议按已结束会话的结束时间计算；未结束或案件保全的会话不进入清理候选。
- 初始 `auto_delete_enabled=false`。超过一年仅显示候选数量及占用空间，不删除，租户无权自行打开或缩短该总控策略。
- 后期由总控显式开启：先预览范围并确认归档和保全状态，再按租户小批次执行。记录操作者、策略版本、删除范围、数量、时间和归档标识。
- 以完整会话及附件作为清理单位，避免按消息日期剪断原有哈希链；重试幂等，必须校验租户和候选条件，不能使用无租户的整表清理。
- 导出文件、缓存、归档及备份另设访问控制和到期策略；删除在线数据不等于所有备份立即消失。
- 现有哈希链可用于完整性检查，但不能防拥有数据库高权限者重写整个链。关键审计定期输出到访问受限的独立归档；生产可采用不可变存储。本文不承诺证据具备某种司法效力。

## 10. 页面结构

### 10.1 新总控后台

1. 总览：租户状态、用户/在线人数、待处理异常与配置完整度。
2. 租户管理：创建、唯一域名、状态、模板、功能授权、强制配置、一键进入。
3. 后台账号：按租户查看管理员/客服/代理后台登录标识，创建初始或额外账号；密码只重置不展示。
4. 业务监管：租户选择后只读查看用户、代理、订单、资产、实名、充提、管理员及统计。
5. 在线用户：各租户数量、分页明细、最近页面。
6. 客服审核：按租户/用户/客服/时间检索、只读监督、受控导出。
7. 总控审计：进入、退出、敏感读取、导出、修改及失败访问；不可通过界面编辑审计正文。
8. 总控安全与留存：总控账号、MFA、会话撤销、聊天留存及清理开关。

### 10.2 租户后台

沿用现有菜单和业务页面，不重写另一套后台。新增/调整：顶部平台名称、在线人数可点击及明细、授权不足/总控锁定状态、可创建的本租户后台人员，以及总控访问标签页的身份横幅。

租户看不到其他租户列表和总控账号。页面、按钮、搜索建议、统计、导出、错误提示都不能泄露其他租户数据。

## 11. 初始化、迁移、部署与回滚

### 11.1 新租户初始化

复制经过审核的版本化配置模板：基础角色、币种/产品的安全默认值、功能默认关闭状态、品牌占位和普通配置。创建初始后台账号时独立设置一次性密码并要求首次修改。

不复制用户、代理关系、订单、资产、实名、会话、真实管理员密码、收款地址、SMTP/短信等密钥。新租户保持草稿，补齐域名/证书/必要配置后才能开放。初始化失败可幂等重试，不能留下半初始化且可注册的租户。

### 11.2 停机迁移

1. 固定并审核代码版本，清点全部表/文件/缓存/任务/模拟后端；完成隔离清单、唯一键冲突和孤儿数据报告。
2. 在隔离测试库用脱敏数据演练迁移及恢复，验证实际 MySQL 的约束和并发行为，不只依赖 H2。
3. 安排停机：停止用户及后台写入、定时结算、消息处理、模拟服务写入；排空在途请求。记录未完成订单、任务进度和切换时间。
4. 备份并验证数据库、私有文件、配置、当前发布包与必要运行状态，确认恢复可用。
5. 创建默认租户，给所有旧业务数据回填同一 tenant_id，保留原 ID、余额、关系、时间和历史内容；全局菜单/公共行情/总控数据按分类处理，不机械加默认租户。
6. 先核对行数、关键金额汇总、外键关系及历史消息哈希，再完成 NOT NULL、租户唯一索引和复合外键。资金按原始币种和账户类型核对，不用浮点数求和。
7. 生成后台登录注册项并处理名称/旧邮箱别名冲突；默认租户原超管仍是租户负责人，新建独立总控身份，不把全部旧超管自动升级为总控。
8. 部署所有端和后端新版本，禁用旧版本业务入口；清理旧私有缓存并切换到租户键，撤销无租户声明的旧会话。
9. 先在维护状态验证默认租户完整业务、第二租户隔离、域名路由、总控会话、私有文件和模拟后端。
10. 按幂等业务规则恢复结算，补偿停机期间到期任务，验证没有重复结算和漏单，再开放业务。

迁移使用审核过的版本化脚本，不依靠 Hibernate ddl-auto=update 自动完成数据回填和约束变更。生产 schema 使用校验模式或等价受控流程；DDL 是否可事务回滚按实际 MySQL 行为处理，不能假设一次事务能撤销全部变更。

### 11.3 回滚边界

- 开放新写入前，可在再次确认停写后恢复已验证备份与旧发布包。
- 一旦新增租户或产生新业务写入，禁止直接用旧备份覆盖丢失新数据，也禁止把没有租户校验的旧应用连到多租户库。
- 此后优先前向修复，必要时停机保存增量并执行经过验证的数据重放/恢复方案。回滚不是直接恢复几个旧 Java 文件。

## 12. 实施阶段与验收门槛

### 阶段一：隔离基座

完成表/接口/任务分类、租户上下文、域名绑定、账号与登录、Repository 边界、数据库约束、缓存和文件边界。默认租户迁移在测试库演练。未完成该阶段不开放新租户。

### 阶段二：业务全覆盖

迁移用户、代理、权限、资金、交易、产品、实名、配置、客服、站内信、模拟身份及后台任务；实现功能授权和关闭后的存量处理。必须先做到隔离正确，再做总控捷径。

### 阶段三：总控及在线功能

实现独立总控前端、只读监管、一键租户访问、真实操作者审计、账号开通、在线人数与最近页面、留存配置。总控直接业务权限在此阶段按已确认范围实现。

### 阶段四：回归、演练和上线

至少构造默认租户、A、B，以及多个管理员/代理/用户，验证：

1. A/B 可用相同用户邮箱注册且账号密码找回互不影响，验证码不能跨租户消费。
2. 后台账号名全局唯一；管理员和代理不会因重复邮箱或账号/邮箱碰撞登录错误身份。
3. A 令牌访问 B 域名、替换用户/订单/附件 ID、伪造 Host/转发头/tenant_id 均拒绝且无副作用。
4. 列表、详情、数量、搜索建议、导出、统计、批量操作、原生 SQL 与 EntityManager 路径不越界。
5. 缺少上下文、异常后线程复用、异步重试、模拟后端、WebSocket 与缓存碰撞不串租户。
6. 普通租户超管不能创建总控、修改锁定策略、绑定别人的角色/代理，不能打开被禁止功能。
7. 总控查看页不能修改业务；总控进入 A 后可执行 A 的超级管理员业务操作但不能写 B。
8. 一次性票据过期/重放/被错误浏览器消费失败；访问会话即时撤销、超时有效；多标签页 A/B 不互换令牌或请求目标。
9. 总控操作不生成隐藏管理员、不挤掉租户登录、不通知进入；业务流水及独立总控审计真实完整。
10. 资金调整、充提审核、重复请求和并发结算在真实 MySQL 下无重复入账、无丢失更新、审计与业务提交一致。
11. 关闭期权/理财等不新增订单，但存量结算、历史和必要的资金退出不被阻断。
12. 域名切换后原数据不变、旧域名拒绝、未知主机不落默认租户；登录与业务配置缓存及时更新。
13. 在线总数与分页范围一致；模拟账户不重复；最近页面只存白名单且没有敏感参数，统计刷新符合误差说明。
14. 客服队列、转接、图片和导出隔离；总控监督不修改已读状态；自动清理关闭时超期记录不删除，开启后的演练不跨租户且尊重保全。
15. 迁移前后行数、资金、未完成订单、角色关系和证据一致；恢复演练成功且不会把旧无隔离代码接入新多租户库。

源码检查、接口测试、浏览器真实后端联调、真实 MySQL 并发测试、迁移演练分别留证。字段隔离不能只靠“页面看起来正常”验收。对约 100 人同时在线及导出/结算并发做压力测试后才能给出容量结论。

## 13. 参考与边界

本方案主要依据用户确认和本地代码核查。外部资料用于校核通用安全原则，不代表已完成项目实现验证：

- [OWASP 多租户安全指南](https://cheatsheetseries.owasp.org/cheatsheets/Multi_Tenant_Security_Cheat_Sheet.html)：租户来源需绑定已验证身份，数据库、缓存、异步任务及存储均需隔离；共享表策略需要覆盖性验证。
- [MDN sessionStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/sessionStorage)：按源和标签页分区，以及 opener 导致初始存储复制的行为；不能仅依赖浏览器存储实现访问控制。

用户说明监管目的，但尚未确定司法辖区。本方案只给出技术上的可追溯、访问控制和留存配置，不推定隐蔽访问是否合法，不替代正式的授权与隐私告知安排。
