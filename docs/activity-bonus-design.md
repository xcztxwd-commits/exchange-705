# 活动公告与体验金

## 需求与现有业务分析
现有工程为 Spring Boot/JPA + Vue 3，分移动端、PC、后台。普通公告只有公开文案，无指定收件人、回执或领取记录。真实账户分 FUND、CONTRACT、OPTION，模拟账户独立；此前真实交易统一要求实名。

## 本次设计
- 保留普通公告，后台增加“活动公告”页签。活动可草稿、启用、暂停、关闭；开始/结束时间使用服务端 UTC，模板不允许发送。
- 默认活动 300 U、最近 3 天登录；配置金额、登录窗口、名额、总预算、多语言标题/正文/规则/按钮、礼盒/彩带/无动画、自动弹出。后台批量指定用户 ID，每批最多 1000，去重且校验用户；不自动给全部客户发钱。
- 发送不等于收到。分别保存发送、客户端收到、点开、关闭、领取及打开/关闭次数。关闭但从未打开可独立筛选。收件人只能查看和操作自己的消息，关闭后站内信仍可重开。
- 独立 trial_account 保存本金，绝不写入可划转/提现账户，也不计入可提现总资产。真实订单新增 trial_reserved 字段，快照每笔本金出资。领取和交易同事务提交，用户行锁、活动锁、乐观锁及唯一收件人约束防止重复入账。
- 合约和期权下单优先冻结体验金，实名用户可补真实余额；未实名只允许体验金足额的订单。撤单按原资金来源退还。平仓净亏损（含合约手续费）先扣本单返还及未占用体验金，再扣真实资金；已占用其他订单的本金不能挪用。净收益进对应真实交易账户，本金仍留体验账户。未实名的正收益仍不可提现。
- 体验金无可用余额时不能绕过实名新开仓，但已有订单仍可平仓/结算，已有体验金挂单可继续撮合。提现一律检查真实 KYC 审核结果，不复用交易例外。
- 活动到期/暂停只阻止新领取，不追缴已领取本金，不强行关闭客户持仓。发过的活动金额和资格不可改变，可复制模板另发；文案可编辑，预算不能低于已发金额。
- 纯 CSS 礼盒/彩带，无 GIF 下载、第三方动画依赖或远程追踪。使用原生 dialog，键盘关闭、焦点管理、减少动态效果偏好。文本插值而非 v-html，避免后台内容变成脚本。

## 边界
- 所有资金规则由服务端实施，前端只展示和提示。体验金与模拟资金完全不同。
- 0 天登录窗口表示不限登录时间；资格在发送和领取时双重校验。关闭活动不删除收件人历史。
- 默认预算 300000 U，最多 1000 次领取，每活动每用户一次。仅管理员（非代理）且具备公告操作权限可管理。
- 小批次投放使用同步事务；超过 1000 人应分批，不在 Web 请求中创建不受控大任务。
- 上线前须按实际运营地区审核促销、交易准入和实名要求；本功能不构成合规豁免。

## 使用入口
1. 后台“公告管理”切换至“活动公告 · 体验金”。新建活动默认是草稿，不会自动投递。
2. 编辑金额、近期登录条件、预算、名额、起止时间、动画和语言。多语言编辑支持现有 20 种语言；文案参数为 `{amount}`、`{days}`。系统按钮内置简中、繁中、英语、日语、韩语，其余语言使用英语；活动正文使用管理员指定的回退语言。
3. 保存为模板后可复制为新活动；确认内容后启用，使用“发送”输入目标用户 ID（逗号、空格、换行均可）。发送前二次确认，返回成功、重复和不符合资格数量。
4. “回执”查看发送/收到/打开/关闭/未打开即关闭/领取，可按用户筛选，并查看该用户体验金账户和流水。
5. 客户真实账户右上角站内信按钮打开活动列表；已有站内信页面也提供活动入口。关闭不会删除。链接可带 `?activity=消息ID` 打开独立弹窗，服务端仍检查收件人所有权。
6. 默认文案已预填“为回馈新老客户，最近 3 天登录的客户可领取 300 U 体验金”，并提示本金仅可交易、不可提现。领取不需要充值。

## 代码与接口
- 服务端：`exchange-backend/src/main/java/com/gtcfesk/exchange/activity/`；后台控制器 `admin/AdminActivityController.java`。
- 客户端：移动端及 PC 的 `ActivityCenter.vue`、`TrialAccountCard.vue`；PC 实际桌面交易页已分开真实资产余额和包含可用体验金的下单余额，避免体验金计入可提现资产。
- 后台：`ActivityManagement.vue`，复用现有公告菜单权限；代理账户不展示入口且 API 拒绝访问。
- 客户接口 `/api/activity/inbox`、`/messages/{id}`、`/messages/{id}/event`、`/messages/{id}/claim`、`/account`、`/ledger`。
- 后台接口 `/api/admin/activities`、`/{id}/send`、`/{id}/stats`、`/{id}/recipients`、`/users/{id}/account`、`/users/{id}/ledger`。
- 客户端响应不包含后台活动名、预算、已发金额等内部字段。活动与账户 API 设置 `Cache-Control: no-store`。模拟账户不加载真实活动入口或发起体验金请求。

## 发布与已知边界
- 本轮完成代码、构建及隔离测试；没有替换正在运行的 Docker 服务，也没有创建生产活动。
- 增量脚本：`exchange-backend/src/main/resources/db/migration/create_activity_bonus.sql`。发布时先备份，再执行增量迁移并发布兼容后端，最后发布移动端、PC 和后台。此脚本不是自动启动即执行的 Flyway 迁移；开发环境 `ddl-auto=update` 可创建同样结构。
- 开始/结束时间按 UTC 录入，客户端按客户时区显示；服务器应统一 UTC。到期只限制新领取，已领取本金无额外失效日期。
- 自动弹窗在页面可见时每 15 秒检查，不承诺即时推送。回执是客户页面成功请求的记录，不是邮件送达证明。
- 体验金账户本金与真实账本已隔离。可选的历史净资产估值模块仍采用原有持仓浮盈亏估值口径，未改成“体验金可吸收亏损后的真实净资产”口径；不要把该估值曲线作为可提现余额。提现以真实账户和实名校验为准。
- 恢复旧代码前必须先暂停活动并结清体验金参与的持仓，保留本金和收益流水；不能直接删表或回退到不识别 `trial_reserved` 的旧交易结算代码。
