# 日语补校验：此前未完全确认的分支

## 范围
本轮只补查 PC 与手机前台的异常响应和动态文本来源。服务器后台界面、客服不在范围内；业务小歧义暂不调整。不重复声称已经完成的页面测试是本轮新增验证。

## 实际修复
双端公共请求层在服务器没有 message/error、Axios 生成 `Request failed with status code NNN` 时，过去会直接显示英文。现使用已有日语：

> 処理結果を確認できませんでした。状況をご確認ください（HTTP 503）

保留 HTTP 状态码，不将写请求的异常误报为确定失败，不建议重复提交。该句是项目语义翻译，不宣称是其他平台的官方原句。服务器明确返回的业务说明和未知诊断内容仍优先保留，不被通用提示覆盖。非日语分支未改变。

## 补校验结果
- 双端合计 30 项请求错误断言通过。新增 HTTP 400、403、404、429、500、502、503、504 无说明响应；验证自定义诊断、未知业务说明不被覆盖。测试使用 Axios/Pinia 桩，未发送网络请求。
- 结构校验通过：19 个语种、37,829 次字典查询、每端 333 项日语 UI 文案；含既有指标代码保护检查。结构通过不等于每一句获得母语者认证。
- 双端生产构建通过；PC 仍有构建包体积警告。
- 本轮没有重新执行前次 91 个浏览器状态，不将旧结果计为本轮页面验收。

## 动态内容核对及边界
1. 公告列表和首页公告请求携带当前语言参数；服务端按该语言筛选，前端有语言变化后的旧响应保护。这是源码路径确认，不是对生产公告正文的语言认证。
2. 公告标题/正文仍展示服务器提供的原文；语言标记为 ja 并不能证明内容本身是正确日语。
3. 双端 `FinancialPurchase.vue` 的 `product.description`、`Verification.vue` 的 `reviewRemark` 及 PC `DesktopTrade.vue` 的审核说明直接显示返回内容。这些属于前台可见内容，而不是要求后台界面切换语言。
4. 未取得完整生产公告、商品说明、审核备注与所有未知错误样本，无法确认其全部日语质量。没有把动态说明删掉、伪造翻译、用通用提示掩盖真实原因。
