# 历史源恢复：功能与交互设计

日期：2026-10-07。阶段：设计评审。本文与交互预览不接入生产接口，不执行行情写入。

## 目标与入口

管理员选定品种和历史区间，把误操作造成的历史偏移、控盘轨迹恢复为该品种当时的原始源 K 线。时间输入与图表框选共用一个选区，支持单根修复和多根修复。

建议在现有「AI 控盘」内增加「历史源恢复」「恢复记录」页签，复用品种选择器及租户、实盘/模拟环境上下文。在控盘任务历史行增加「恢复此段源数据」入口，进入恢复页并预填任务已提交的实际时间范围。

现有「一键恢复原始行情」继续处理当前报价。新功能的操作范围是选定的历史分钟，不联动修改当前偏移、运行任务、已成交订单、资金或结算结果。

## 页面与操作流程

1. **选品种和区间**：开始时间、结束时间、显示时区。结束时间包含该分钟，例如 17:21—17:21 表示恢复一根一分钟 K 线。
2. **图表定位**：同图显示恢复前的 K 线与原始源收盘价，点一根选单根，拖动选择多根；选区两端可继续拖动，时间输入同步变化。
3. **预览恢复**：列出实际范围、源数据覆盖情况、需要改动的分钟数，展示选区 OHLC 恢复前后对比。可切换「恢复前」「恢复后预览」查看异常影线是否消失。
4. **确认恢复**：确认品种、区间、时区和改动数。源齐全、快照保存成功后才可执行；按钮显示「确认恢复 N 根」。
5. **查看结果**：显示已恢复数、任务状态和恢复记录，刷新图表。记录包含操作人、实际区间、源身份、快照、校验结果和操作时间。

### 图表选区

- 默认一分钟；五分钟、十五分钟、一小时用于定位较大区间，最终仍恢复完整分钟。
- 点击一根大周期蜡烛选中它实际覆盖的全部分钟。界面明确展示展开后的起止范围和分钟数，确认依据展开后的范围。
- 拖动选区边界按分钟吸附；反向拖动也可用。图表平移与框选使用明确的模式按钮，避免一次拖动同时改变视口和选区。
- 滚轮缩放，底部时间缩略轴定位，向左翻页加载更早数据；切换周期或时区保留绝对 UTC 选区。
- 日期跨日显示年月日；时间字段展示时区。夏令时不存在的时间拒绝，重复时间要求选择明确 UTC 偏移。
- 键盘可直接编辑时间；触屏支持点选起点、终点，避免依赖鼠标拖动。

### 预览与异常状态

| 状态 | 页面行为 |
| --- | --- |
| 原始源齐全 | 展示改动数和价格对比，可确认 |
| 已经是原始源 | 显示「所选区间无需恢复」，不生成重复改动 |
| 部分分钟缺源 | 标出具体缺失区间，提供「补采原始源」；补采完成后重新预览 |
| 上游不支持该历史粒度/范围 | 明确显示不可恢复原因，不用其他周期猜测分钟 OHLC |
| 当前分钟、未来时间 | 拒绝；只能选择已结束的历史分钟 |
| 历史输入仍在补齐/最终化 | 等待该区间提交稳定后重新预览 |
| 预览后历史或源身份改变 | 原确认失效，提示重新预览 |
| 已封存的旧历史 | 显示受保护区间，普通恢复不能覆盖 |
| 提交后超时或刷新 | 查询原任务和原请求键，不自动重复提交 |
| 大区间执行中 | 显示已完成分钟数，可离开页面再查询 |

休市分钟不补造 K 线。只有原始源的交易日历或确切记录能够证明休市，才标为休市；不能确认的空白列为缺失。不得用平台自定义休市设置推断上游源的历史。

V1 对选定的有效历史分钟要求原始源全部齐备再提交。执行分批后若失败，显示已提交范围和未完成范围；不把部分成功标为全部完成，支持继续原任务或撤销已完成部分。

## 恢复记录与撤销

列表字段：品种、区间、显示时区、恢复分钟数、状态、操作人、操作时间。详情展示备份和源快照的校验摘要、实际提交进度及受影响周期。

撤销使用本次保存的恢复前历史快照，只撤销该操作对所选分钟的展示修正。撤销前校验所选分钟仍由本次恢复版本管理；被后续恢复或其他修正覆盖时拒绝直接撤销，并展示冲突分钟。已有订单和结算结果不重算。

## 数据与实现方向

### 复用现有能力

- 管理端已有 `ManualOrderChart.vue`、`manualOrderChart.ts` 和 ECharts：复用历史加载、缩放、区间标记和时区处理，抽取最少的共用选区逻辑；不要复制手工订单的开/平仓业务。
- 原始源数据已有 `market_source_candle`；恢复前展示来自混合分钟、控盘样本、发布段及手动偏移点。
- 写入沿用 `MarketRuntime` 的真实运行进程、租户上下文、写者代次和短事务。新增受权限控制的业务命令，不将临时运维脚本或 JVM attach 变成产品入口。
- `SourceHistoryGapRepair` 可复用规范化、源身份和缺口判断，但现有普通补采会保护控盘区间，不能直接把它当成恢复命令或取消其保护。

### 独立恢复账本

建议新增两张有租户隔离约束的表：

- `market_history_restore_job`：品种、请求键、源身份、实际 UTC 区间、预览摘要、状态、提交进度、操作人和时间。
- `market_history_restore_minute`：任务、分钟、恢复前展示快照、经核验的完整源快照、两者校验和及生效版本。

展示合并时，已确认恢复的分钟优先使用本次保存的原始源快照；其他分钟继续走原有合并逻辑。原始源、控盘任务、样本、手动点及原发布证据保留。后续旧任务最终化不能再次把已恢复分钟改回错误轨迹。

恢复撤销和后续再次恢复均记录独立版本。重叠操作按最新已提交且有效的版本确定展示，不能在不同接口中产生不同优先级。

源使用当时同品种、同提供方的一分钟 OHLC；须确认分钟结束且数据完整。实时快照、未结束蜡烛、大周期拆分、当前价格平移或插值均不能充当历史源。价格保持原始 Decimal 精度，前端只按品种精度格式化。

### 执行及缓存一致性

1. 预览只读恢复前历史；需要补采时，外部请求在写事务之外执行。准备阶段保存经核验的源候选，记录源身份和覆盖证据。
2. 确认校验预览令牌、所选区间历史摘要和源路由；当前实时偏移变化本身不应使不相交的历史预览失效。
3. 写者按至多 500 分钟的小批次执行，保留现有事务时间预算。每批的恢复前快照、恢复源快照、恢复进度和展示版本在同一事务提交；失败批次回滚。
4. 为品种增加单调递增的 `historyRestoreRevision`，最新 K 线、历史分页、批量接口及 WebSocket 使用同一展示版本。
5. PC/移动端监听恢复版本，清理该品种所有周期缓存并重载；丢弃旧版本的迟到响应。不能只改变现有发布计数，因为手动偏移优化分支会跳过历史重载。
6. 大周期由修正后的分钟聚合；同时间只返回一根蜡烛，源日历和周期锚点沿用现有规则。

历史读取还需修正已有的「先 LIMIT 原始源行，再过滤非周期边界快照」问题。应在限量前选择有效周期蜡烛，保证恢复的分钟在较小分页中也能返回。本会话已观察到正常 200 根页可见，而 8 根历史页可能遗漏同一分钟。

### 建议接口与权限

接口挂在 `/api/admin/ai-control/{symbolId}/history-restore`：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /chart` | 同一窗口的恢复前与原始源、覆盖情况、历史版本 |
| `POST /preview` | 规范化区间、核验源、生成预览令牌；补采未完成时返回准备状态 |
| `POST /jobs` | 用预览令牌和幂等请求键提交；202 仅表示受理 |
| `GET /jobs`、`GET /jobs/{jobId}` | 记录列表及持久进度，支持按原请求键查询 |
| `POST /jobs/{jobId}/undo-preview`、`POST /jobs/{jobId}/undo` | 校验撤销范围并提交独立撤销命令 |

请求传绝对 UTC 起止时刻和显示时区，不接收价格或客户端指定的租户。服务端从认证上下文绑定租户及实盘/模拟环境。

新增明确权限 `ai_control:restore_history`、`ai_control:undo_history_restore`；沿用查看权限读取页面、图表和记录。查看角色不能执行恢复或撤销。

## 首版验收重点

- 复现 2026-10-07 17:21 USD/JPY：源 OHLC 显示为 158.221 / 158.236 / 158.210 / 158.229，异常下影线消失，相邻分钟一致。
- 单根、正向/反向拖选、时间输入、跨日和时区切换的实际 UTC 范围一致。
- 源缺失、未结束分钟、受保护历史、预览失效及无权限都不产生恢复写入。
- 手动偏移点、目标样本、保持段、已发布轨迹均可按区间恢复，未选部分继续保持原展示。
- 1m/5m/15m/1h、最新图、历史小分页、批量接口、PC/移动端缓存结果一致；刷新、断线及重启后保留。
- 重复提交、执行中重启、分批失败、继续原任务、重叠修正和撤销均有可查询结果。

## 本轮交付

推荐「时间输入 + 图表框选 + 对比预览」同页方案。交互预览采用本会话保存的恢复前行情片段演示，所有确认与撤销均为本地预演。后台功能、数据库迁移和生产部署尚未实施。
